## 直接使用

无需打开 Visual Studio。程序已经构建到 `bin\host\StepRobot.App.exe`。

- 双击 `demo.cmd`：用明确标记的**软件测试桩件**演示状态采集和步骤预览；不会连接 Studio。
- 双击 `capture-studio.cmd`：从已启动的 Studio 虚拟控制器采集 10 秒，结束后显示日志路径。
- 在此目录的 PowerShell 运行下面的命令：

```powershell
# 帮助
.\run.cmd --help

# 核查 C# 能否加载真实厂商 C++ SDK；不建立连接
.\run.cmd --diagnose

# 在 Studio 的虚拟控制器启动后，只读采集 10 秒
.\run.cmd --ip 127.0.0.1 --seconds 10

# 脱离 Studio 做纯软件测试，生成独立 JSONL 日志
.\run.cmd --demo --seconds 3
```

每次默认生成一个不同的 `logs/run-*.jsonl` 文件。按 Ctrl+C 取消采集或等待，程序停止轮询后关闭日志与 SDK。控制台会打印日志完整路径。

## Studio 需要到哪一步

1. 导入已下载的 **SR175-3200**。
2. 创建并保存机器人系统/工作站。
3. 在“控制器”栏启动虚拟控制器，等右下角显示“运行中”，再打开 HMI。
4. 查本机监听，并核对监听进程属于虚拟控制器：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 30312 -ErrorAction SilentlyContinue
```

软件主窗口打开、试用有效、模型下载完成，都不等于 SDK 端口已服务。端口监听后，还需用上位机验证 SDK 握手、数据读取，并对照 HMI 的关节与位姿数值。若虚拟控制器未开放 SDK 接口，需要确认厂商支持的接入方式；不能据 TCP 是否能连就断言 SDK 可用。

## 两条 SDK 接入方式

| 方式 | 当前能力 | 依赖与边界 |
|---|---|---|
| 默认：C# → 自建原生桥 → 厂商 C++ SDK | 已在本机虚拟控制器完成连接和状态采集 | 已提供 `StepRobot.Native.dll`，无需厂商 C# DLL。C# 适配层不提供运动、清报警或 IO 写操作；尚未验证真实机械臂 |
| `--dll`：厂商 C# SDK 反射适配 | 原有只读采集、倍率/使能/关节点动序列 | 真 `Robot-SDK-CSharp.dll` 仍未提供；字段和调用行为需要拿到配套真库后验证。当前测试只能覆盖软件桩件 |

桥接层使用项目已有 C++ 头文件和 `Robot-SDK.lib` 编译，不仿造厂商 DLL，也不依赖非公开网络协议。依据 [Microsoft P/Invoke 文档](https://learn.microsoft.com/en-us/dotnet/standard/native-interop/pinvoke) 使用 C ABI 互操作。

如后续取得真 C# DLL，可先只读运行：

```powershell
.\run.cmd --dll '.\libs\Robot-SDK-CSharp.dll' --ip 127.0.0.1 --capture-only --seconds 10
```

## 纯软件的完整序列测试

以下数值只供桩件测试，**不是 SR175/3200 官方限位**。

```powershell
.\run.cmd --demo --allow-motion --allow-stub --seconds 1 `
  --limits '-170,170;-120,120;-175,175;-120,120;-140,140;-360,360' `
  --joints '20,15,-10,5,90,-170'
```

`--allow-motion` 必须同时给出完整六轴目标和限位。格式错误、NaN、无穷值、上下界错误和越界目标会在连接前被拒绝。默认 C++ 只读桥接不接受该选项。测试桩件的到位响应不表示真实运动规律。

## 数据导出

将命令中日志路径替换成刚生成的文件：

```powershell
& 'D:\Anaconda\anconda\python.exe' .\tools\analyze_run.py '.\logs\run-实际文件名.jsonl' --out-dir reports
```

生成遥测 CSV 和关节/倍率/使能时间图。日志记录 SDK 版本、后端和 `dataKind`：`software-test` 是测试数据；`controller-unvalidated` 表示控制器数据尚未完成机型/单位/坐标一致性验收。日志中的 SR175/3200 为本项目预期机型，不是自动识别结果。

界面采样时间是 PC 读取时间；SDK 内部缓存的实际刷新周期尚未验证。默认 200ms 落盘不等于真实控制周期，也不能据此宣称高频跟踪精度。

## 从源码重建

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

脚本依次编译原生桥、构建 C#、执行测试、发布运行包；任一步失败即停止。依赖：Windows x64、.NET 8 SDK、`D:\VSBuildTools`、本项目 `_extract/sdk` 中的厂商 C++ 库。普通使用只需 .NET 8 运行时及配套 VC++ 运行库。

2026-09-27 已用 WinGet 安装 **.NET SDK 8.0.425 / .NET 运行时 8.0.31**，保留既有 .NET 10 运行时。[Microsoft 安装说明](https://learn.microsoft.com/en-us/dotnet/core/install/windows) 区分了 SDK 与运行时。

退出码：0 正常；1 采集或步骤失败；2 参数或加载依赖问题；3 连接失败；5 测试桩件保护拒绝；130 用户取消。
