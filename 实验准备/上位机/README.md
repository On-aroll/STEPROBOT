## 当前可以做什么

- 双击 `demo.cmd` 进行明确标记的软件桩件演示，无需启动 Studio。
- 双击 `capture-studio.cmd` 从已启动的本机虚拟控制器采集 10 秒，生成独立日志。
- `run.cmd --diagnose` 验证 C# 加载真实厂商 C++ SDK，读取库版本。
- `run.cmd --ip 127.0.0.1 --seconds 10` 尝试从本机控制器只读采集状态。
- 将采集记录写入独立 JSONL 日志，再用 `tools/analyze_run.py` 导出 CSV 和图表。
- 保留 `--dll` 厂商 C# 反射适配和显式序列执行；真 C# DLL 尚未提供，运动行为仅在桩件中验证。

默认地址为本机，默认不下发写命令。新增的 C++ 桥接适配层只读，不能用于使能、点动或 IO 写入。

## 结构

```text
StepRobot.App                    参数、连接、采集、取消、日志、步骤报告
  ├─ StepRobot.Adapter.Native    P/Invoke → 自建 C ABI → 已有厂商 C++ SDK（只读）
  ├─ StepRobot.Adapter.Reflective 厂商 C# DLL 或明确标记的测试桩件
  └─ StepRobot.Core              状态轮询、软件校验、序列执行、日志
native/bridge.cpp                原生桥源码，无 C 形式的运动/IO 导出接口
native/build.bat                 MSVC x64 /MD 构建
```

## 本次修正

- 帮助命令、严格六轴输入校验、明确目标、默认本机地址；无效输入在连接前拒绝。
- 未知模式、NaN、无穷值、无效限位和不完整反馈不能被判成允许运动或已经到位。
- 到位等待要求命令之后的新采样；状态失效时中止，Ctrl+C 可取消等待。
- 退出先停止轮询回调，再关闭文件和连接，避免后台继续访问已关闭的资源。
- 厂商模式用数字返回时按厂商枚举映射，0 对应 Manual。
- 每次默认独立日志，记录预期机型、后端、数据类别、目标与限位。日志中的机型未自动识别。
- 分析器支持没有运动步骤的只读会话；把终点偏差正确称为“终点关节误差”，不当成整段轨迹跟踪精度。

这些校验属于应用层逻辑，不能代替控制器与实验室的安全措施。若将来使用真 C# DLL 发命令，还需验证接口签名、机型限位、单位与坐标，并完成现场验收。
