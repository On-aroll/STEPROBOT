## 0. 一页结论

机器人是 **STEP（上海新时达）** 工业机器人，控制器 IP 固定 `192.168.39.220`。五份文档不是并列关系，而是四层：

- **SPad 操作软件（267 页）** = 人机层，第一次上机、示教、标定、排障全靠它，**必读**

**不阻塞的部分现在就能做完**：本机 VS2022/.NET 7 环境、网络拓扑预配置、链路自检程序、机器人脚本骨架、现场 SOP。做完这些，拿到 DLL 当天即可出结论。

## 1. 四层通路详解

| 文档 | 页数 | 定位 | 关键事实 |
|---|---|---|---|
| 操作软件使用说明书（SPad 示教器）V1.8.1 | 267 | PC 版虚拟示教器 | 顶栏 `STEP > 切换机器人` 填控制器 IP；登录 `Admin/123`（超级密码 511011）；T2/AUT/AUT EXT 三种运行方式；**点动限速 250mm/s** |
| 用户编程手册 V1.8.1 | 147 | 机器人脚本语言 | 类 IEC 61131-3 结构化文本；`PTP/Lin/Circ`；`MAIN` 主程序 + `ProgCall(project0.sr\test)`；函数嵌套 ≤8 层 |
| Socket 功能说明书 V1.8.0 | 36 | 报文级上下位交互 | **仅 TCP**；机器人可做 Server，端口 `8889`；`SocketRecvPos`/`StringsToPos` 直接填位置变量；单帧 ≤511 字节；**无自动重连** |
| Modbus 通讯说明书 V1.8.0 | 30 | 从站信号级 | 机器人**只能做从站**；TCP 端口 `502`；**RTU 与 TCP 互斥**；数据只映射到通用 IO：`Word1~4 → DI33~36`，`Word5~32 → AI5~32`；**无运动控制寄存器表** |
| SDK 使用说明 C# V2.3 + SR.SDK C++ V2.4.1 | 161 + 6 文件 | 上位机接管 | PC 为 TCP 客户端 → 控制器 `30312`（固定端口，**单客户端独占**）；需控制器 **≥ V1.8.0.20240531_0712** |

**选型判断**：SDK 能力最全（读实时位置、写任意变量、下发语句流），实验自动化走它没有疑问。要避免两个误判：

- 别指望 **Modbus** 控轨迹——手册里根本没有位置/速度命令字，它只能搬运 IO 电平。
- **Socket** 是"机器人脚本主动收报文"，需要机器人侧先写好解析程序，属于给视觉/测量引导抓取用的旁路，不是主控通路。

三个端口（30312 / 8889 / 502）互不冲突，可以并存；但 30312 唯一，**示教器与其它上位机会抢**，这一点在第一阶段联调时最容易踩。

### 3.2 本机安装 —— 已完成并验证（2026-09-18）

```powershell
winget install --id Microsoft.DotNet.SDK.8 --exact   # ✅ 已装 8.0.425
winget install WiresharkFoundation.Wireshark          # 待装
winget install Git.Git                                # 待装
```

实测结论：

- 安装前后对比明确 —— 之前本机 `dotnet --list-sdks` 无输出、无 VS2022 目录；现在 SDK 8.0.425 就位，
  可用运行时为 **5.0.3 / 6.0.23 / 8.0.31**。
- **目标框架定为 `net8.0`，不是 net7.0**。原因实测过：`net7.0` 用 SDK 8 能编译成功，
  但**启动即失败**，报 `You must install or update .NET to run this application`——
  默认 roll-forward 不跨大版本，而 7.x 运行时根本不存在。厂商手册 1.3 写的是 .NET 7「建议相同或更高」，
  net8 合规且仍有安全更新。另加 `RollForward=LatestMajor`，换台电脑也不会卡在这里。
- VS2022 **不是必需的**：自检工具走命令行 `dotnet build` 已验证可编译。
  等要做正式上位机（界面、多文件）时装 ManagedDesktop 负载即可。
- **平台目标必须 x64** —— 厂商 C# 库以 Release x86/x64 编译，工程不能用默认 AnyCPU，
  否则引用 DLL 时 `BadImageFormatException`。

> 这一条正是"能不能编译"和"能不能跑起来"的区别：只看 build 成功会误以为环境就绪，
> 到实验室才发现启动失败。已记录在 `SdkLinkCheck/__test__/说明.md`。

### 3.4 备选通路（暂不投入）

C++ SDK 包本地已具备，但风险明显高于 C#，除非有硬需求否则不建议作为实验主通路：`.lib` 为**静态库**（VS2015 ABI / x64 / `/MD`），Release 必须链 `Robot-SDK.lib`、Debug 必须链 `Robot-SDKd.lib`，混用触发 LNK2038；头文件**零单位注释**（mm/度只能从示例数值推断）；**没有上电接口**（枚举有 `eEnableRobot=1053` 但未导出）；无心跳、无重连、无回调；线上格式为裸内存 + 小端 + MSVC 对齐，改字段即破协议。

### 阶段 1：现场链路联调 —— 不动机（第一次到实验室）｜半天

严格顺序，每步通过才走下一步：

2. `Test-NetConnection ... -Port 30312` 确认 SDK 端口通
3. 启动 SPad → `切换机器人` 填控制器 IP → `Admin/123` 登录
4. `信息 > 系统信息` 核对控制器版本 **≥ V1.8.0.20240531_0712**、本体类型、控制柜名称

8. 跑 `SdkLinkCheck` 自检程序（见第 8 节）：连接 → 读版本 → 轮询全部只读状态 → **不断开也不使能**

- **验收**：自检程序稳定读状态 ≥ 5 分钟无 `-3 通讯断开`；能读到 `getAxisPos()` 数值且与实际姿态一致

### 阶段 2：使能与点动 —— 低速真实运动（需要现场安全条件）｜半天

前置：清场、确认急停可用、工作空间区域已加载、速度给 **15%**。

1. 关节点动 A1–A6 各 ±5°，确认无"零点丢失"告警
2. 切 `世界点动`，`WORLD` + `Default` 工具，空域画 X/Y/Z/A/B/C，确认方向手性
3. 工具 4 点法 + 1 点法标定；工件三点法标定
4. SDK 侧首次使能：`getMotorEnableState()==0` 才 `EnableMotorCmd()`，**之后强制 sleep ≥ 300ms**（手册明写：少于这个时间无法执行下一步）
5. 单条 `JogToRobotAxisposCmd(ePTP, ...)` 小角度走点 → **必须调 `JogToPositionExitCmd()`** 关闭点动通道
- **验收**：同一套代码，SDK 走的点与示教器走的点位置一致（误差在读取精度内）

### 阶段 3：正式实验循环

- 语句流下发：`SDKSimulateProgramLoad()` → `SetModeCmd(START)` → 逐条 `SDKSimulate*ProCmd` → `SDKSimulateProgramSend()` → 轮询 `getProgramState()` → `SetModeCmd(STOP)` → `SDKSimulateProgramKill()`
- **注意语句缓存单次最多 10 条**，超限返回 −1，须先 Send 清空
- 数据采集：全部状态靠**轮询**（SDK 无回调），建议 20–50ms 周期；手册警告"变量获取接口为命令接口，不建议一直进行获取"
- 实验程序纳入 Git；`.srp/.srd` 是文本，可 diff

## 5. 关键约束速查（写代码前先看这页）

| 类别 | 约束 | 出处 |
|---|---|---|
| 端口 | 30312 单客户端独占，与示教器互斥 | SDK P2 |
| 时序 | 使能后与下一步**间隔 ≥300ms** | SDK P13 |
| 单位 | 关节**度**；笛卡尔 `X/Y/Z` **毫米** + `A/B/C` **度** | 由示例推断，**未官方确认** |
| 速度 | `OverrideSetCmd` 是 **0.1~100 百分比**（>1 会四舍五入成整数） | SDK P21 |
| 模式 | 点动**必须在手动模式下** | SDK P15 |
| 缓存 | SDK 语句单次最多 **10 条**，超限返回 −1 | SDK P130 |
| 变量 | 修改要求示教器程序**非运行状态**；`ProcessVariable*` 受预读影响，可能改了不生效 | SDK P29 |
| 全局变量 | 工程名固定 `_global`、程序名 `_project` | SDK P29 |
| 坐标系 | `WORLD` 与 `ROBOTBASE` **不支持修改** | SDK P87 |
| IO 位取 | DI/DO 打包在 `m_DI[64]/m_DO[64]`（`unsigned long`，共 2048 点），须 `(m_DI[0]>>n)&0x01`；AI/AO 32 点 | SDK P24 |
| 强制行为 | 取消 DI 仿真会**复位 DI**；取消 DO 强制**不改变 DO 状态** | SDK P25 |
| 编码 | 中文消息须 `Encoding.UTF8.GetString(Encoding.Default.GetBytes(...))`，否则乱码 | SDK 版本修订 |
| 返回值 | `0` 正常/执行中，`-1` 失败，`-2` 数据收发异常，`-3` 通讯断开 | SDK P3 |
| 到位判定 | SDK **无到位回调**，手册示例用 `Console.ReadKey()` 人工确认或轮询 | SDK P125 |
| **急停** | **SDK 全程没有急停/安全门/防护 API**，安全回路必须留在硬件与示教器侧 | 全文核查 |

脚本语言侧另记：`REAL` 是双精度，但 `NumToString` **只保留 8 位有效数字并补零**；`STRING` 上限 511；`ARRAY` 长度 1–100；`GetCenterByPoints` 拟合误差 >10mm 直接报错；`PathRecMoveFwd/Bwd` 只支持 PTP/Lin/WLin；`BitCheck` 索引**从 1 开始**；`SWITCH` 参数只能 Uint。

## 6. 常见故障对照

| 现象 | 首查 | 处理 |
|---|---|---|
| `init` 返回 −1 | 网段/端口占用 | 断开示教器；`ping`；`Test-NetConnection` |
| 返回 −3 | 通讯断开 | 无 Disconnect API，只能重新 `init(ip,30312)` 重连 |
| `BadImageFormatException` | 平台目标 | 工程改 x64/x86 对齐 DLL；确认 Release/Debug |
| 使能后指令无反应 | 300ms 间隔 | 加 `Thread.Sleep(300)` |
| 报警 `4001` | 机器人没上使能 | 检查使能状态 |
| `3817` | 示教器意外断开 | 重连示教器 |
| `3400` | 找不到变量/非法使用 | 确认示教器里该工程/程序/变量**已存在** |
| `3511` | 程序格式非法 | 检查 `.srp` 语法与语句数 |
| 消息中文乱码 | 编码 | 按第 5 节转码 |
| 改坐标不生效 | 程序在运行 / 预读 | 停下程序；改用非 Process 版本 |

**测试替我们把安全性质的缺陷抓了出来**（每一个都是我先写错、测试后驳回的）：

1. 枚举按**序号**转换：Core 的 `Unknown=0` 撞上 SDK 的 `eManual=0`，会把"手动"读成"未知"——
   而这正是安全闸判断能否运动的输入。已改为按名字映射，认不出就返回 Unknown，绝不给"碰巧对上"的值。
2. **等待超时被记成 executed 并继续发下一条运动指令**（`WaitEnabled`/`WaitFor` 同样中招）。
   已改为返回 `(Detail, Ok)`，未达成即中止整轮。
3. 黑名单子串匹配误杀 `getMotorEnableState` / `getJogRefSys`。
4. `net7.0` 能编译但不能启动（本机无 7.x 运行时）。
5. `--dump` 被网络预检挡住，与其"离线可用"的承诺自相矛盾。

**已验证**：`dotnet build` 0 错误；离线冒烟测试全流程通过；三种退出码（0 / 2 / 3）与文档一致；
安全闸能拒绝全部 7 个命令接口
（`EnableMotorCmd / SetModeCmd / OverrideSetCmd / JogToPositionExitCmd / JogToRobotAxisposCmd / AllAlarmConfirmCmd / ProgramLoadCmd`；
桩件里这些方法被调用就会打印 `[桩件调用] 方法名`，实测输出中一行都没有）。

**仍未验证，且只有现场才能验证**：

1. 真 `Robot-SDK-CSharp.dll` 的**真实接口签名集合**与是否 64 位；
2. 各结构体**字段名**（手册只给 C++ 布局，C# 侧待 `--dump` 与首轮快照揭示）；
3. **单位与角度制**（毫米/度只是从示例数值推断，无官方确认）；
4. 原生依赖是否齐全（C# 包装层若 `DllImport` 了配套原生 .dll，缺文件会在运行期才炸）；
5. 控制器固件是否真的 ≥ V1.8.0.20240531_0712。
6. **反射适配层自身的三条假设**：关节数组靠"取第一个 `double[]` 字段"发现、点动类型靠"找名为 `ePTP` 的枚举成员"选取、
   模式枚举靠去掉 `e` 前缀按名字匹配。真 DLL 若字段顺序或命名不同，这几处会静默读错——最危险的一类错误。

自检程序不依赖字段名猜测——它用反射打印，所以第 2 项一跑就有答案；第 1/4/5 项靠 README 的错误码指引定位；
第 3 项必须在首轮快照时对照机器人实际姿态人工核一次；
第 6 项的处置顺序是固定的：**先跑 `SdkLinkCheck --dump` 拿到真实签名，再改适配层那一个文件，最后才允许跑上位机**。
桩件通过不代表真 DLL 通过，只代表软件闸门逻辑本身没有洞。
