## 日常目标流程

1. 机器人停止、未使能，PLC无未完成动作。上位机可保持PLC连接，动态反馈必须有效。
2. 打开R4.4“导入G代码 / 固定编号…”。默认勾选“导入后自动上传”；导入受支持的G代码后自动转换、保存、Modbus传文件、PLC FTP更新与逐字节回读。
3. 七个文件全部通过，且PLC返回固定工程放行后，软件显示原有编号。用户确认工程为 `pcjob_20261116_201104_7f547f98.sr`，编号为1=capture_home、2=helix_25mms、3=go_home。此为用户确认，不是软件自动读取绑定的结果。
4. 用户按实际编号登记、加载、确认加载、使能、运行。上传本身不加载、使能或运行机器人。

本地转换器仍输出gcode_path；上传快照将其SRP/SRD原字节映射到已绑定的`helix_25mms`文件名，保证编号入口不变。capture_home、go_home和工程变量使用原哈希核对模板。输出仍为空跑运动，没有焊机或送丝控制。

## 受限更新保护

- 原mode0/1仍保持“已有目录不覆盖”；固定工程名被保留，不能用旧模式写入。
- 新mode2仅接受PLC本地确认的**一个既有工程**与七个固定文件：_project.srd、capture_home.srp/srd、helix_25mms.srp/srd、go_home.srp/srd。
- 固定目录不存在则失败，不自动创建其他工程。无目录穿越、系统配置、任意路径或任意文件写入。
- 开始和整个更新期间要求在线、已停止、未暂停、未使能、无动作忙；本地配置、许可或状态失效则中止。
- 更新一开始撤销旧文件放行与加载确认。更新期间禁止PLC使能/加载/运行，保留停止、断使能操作。
- 全部七个文件上传、FTP完成、回读、连接关闭与FINISH确认后才放行固定编号。部分失败、断链、重启、配置改变、复位均不把半更新工程标为可用。
- 这是普通控制逻辑互锁，不是安全控制器或安全停止；不能阻止其他外部控制路径或示教器越过PLC独立操作。
- 覆盖不是文件系统原子提交。失败后目录可能含混合文件；对应固定编号在本版PLC中保持禁止加载/运行，须完整重传成功后恢复。不要用旧版控制桥绕过它。

## 离线配置工具

`Prepare-FixedTarget.ps1`在**明确现有工程及编号**后生成独立目录，包含配置一致的ST、声明/实现TXT和上位机fixed_job_target.json。输出必须是新目录。脚本只生成本地文件，不连接PLC或控制柜，不自动更改正在运行的版本。

上位机从`--control-dir`目录读取fixed_job_target.json；缺少一次性已确认配置时允许本地转换保存，但禁止固定上传。安装配置时将生成的JSON放入R4.4专用control-dir，避免与旧入口混淆。

## 协议增量

命令仍为HR6000..6119，心跳6120..6124，状态6200..6263；frame[18]=2选择固定更新。

| 状态索引 | 含义 |
|---|---|
| 47 | bit0空文件，bit1受限固定更新 |
| 48 | 0x0102 |
| 49 | 固定配置及控制保护已确认 |
| 50 | 固定更新忙 |
| 51 | 固定工程已完整更新，可进入手动加载流程 |
