# 电脑直传与当前 G 代码上传（2026-11-20）

日常上传仍更新 `pcjob_manual_r63.sr / auto_main`，自动运行用 11 号。10 号继续负责手动微调和实验起点。

## 选择传输方式

上传窗口提供两条文件路径：

| 上传方式 | 文件怎么到控制柜 | PLC 的作用 |
|---|---|---|
| PLC 转传 | 上位机 → Modbus TCP → PLC → FTP → 控制柜 | 转传文件、上传许可、回读校验、确认本次版本 |
| 电脑直传（SDK 手册 FTP） | 上位机 → FTP → 控制柜 | 上传许可、回读校验、确认本次版本 |

电脑直传使用 SDK 手册提供的 FTP 文件传输方案。文件不经 PLC 转发，但仍需要 PLC 文件桥在线：机器人生成程序的版本检查与 PLC 发布的版本一致后才能继续加载运行。

顶部选择“实机 STEP SDK”时，上传窗口默认选择电脑直传。上传窗口内可以独立切换方式，并记住手动选择；在 PLC 控制模式下也能使用电脑直传。

无需先点击顶部的“连接”才能上传。顶部连接负责机器人控制和姿态；点击上传窗口中的“开始上传”后，该窗口自行建立传输连接。更换 G 代码并勾选自动上传时，PLC 路线会自动开始上传；电脑直传路线会先展示地址和账号配置。

## 上传当前显示的内容

1. 主界面显示 G 代码时，左侧按钮显示“上传当前 G 代码 / 更换文件…”。点击后，上传窗口直接带入当前显示的源文件内容、转换参数和工艺输出忽略选项。
2. 默认使用屏幕上这份 G 代码快照。即使磁盘原文件随后被编辑或移走，也不会悄悄改成另一份内容。要使用磁盘上的新内容，请明确点击“更换 G 代码”。
3. 点击上传窗口底部的“上传当前 G 代码”，或换选文件后按自动上传选项继续。
4. 换选其他文件后，主界面的 G 代码原文、工程树和轨迹一起更新。上传完成后继续显示本次上传对应的同一份内容；转换失败时显示新文件的错误，并清除旧轨迹。
5. 多文件作业中，工程树里当前查看的 G 代码就是再次打开上传窗口时的默认文件。需要更新整组作业时，可在“更换 G 代码”中一次选择全部文件并核对清单顺序。

## 电脑直传配置

- 控制柜 FTP 地址：使用控制柜 PC 口实际 IP，例如 `192.168.39.220:21`。顶部 SDK 地址的 `30312` 是控制通信端口，上传文件使用 FTP 端口。
- FTP 用户名和密码：现场安装版已预填；公开源码从 `STEP_FTP_PASSWORD` 或 EXE 同目录 `workstation.local.ini` 读取（见[构建说明](../../workstation/README.md)），配置一次即可免重复输入。密码框默认遮挡，点击右侧小眼睛可显示或隐藏，也可按需修改。
- PLC 许可 / 回读地址：使用电脑能访问的 PLC 地址，例如 `192.168.1.188:502`。这不是文件转发路径。

直传窗口标题和路线均显示“上位机 → 控制柜”。成功表示文件已上传并经 PLC 回读确认，之后仍按“登记 → 加载 11 号 → 确认加载 → 使能 → 运行”操作。

## 连续上传与失败后再次上传

2026-11-20现场回执表明：一次直传出现FTP登录失败530后，旧上位机未释放已取得的文件会话；PLC随后因租约超时停在900状态，后续上传被预检挡住。此前切换 `xReset` 可以清掉该状态，但正常使用不应依赖PLC在线强制变量。

连续上传版在通讯正常且会话所有者仍是本次上传时，自动请求清理并确认连接关闭，再释放文件通道。若下一次上传读到上次已超时、已关闭连接的900状态，则核对两次一致的状态后，使用现有文件桥RELEASE命令释放旧会话，再开始本次上传。成功上传的400状态可以直接进入下一次上传。

这次不需要修改或重新下载PLC程序，不切换 `xReset`，也不自动重传文件。正在工作的会话、910连接关闭未知、所有者变化、PLC重启或未确认的命令应答都会停止处理并显示具体结果。上传失败的程序继续保持不可用，直到新的整组文件上传和回读通过。

本次更新通过本地模拟控制柜和PLC，以及实际ST源码解释执行检查，尚未用连续上传版向现场控制柜上传文件。
