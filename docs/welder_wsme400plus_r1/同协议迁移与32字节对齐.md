## 修正此前判断

现场 CoE 读值确实为每方向 15 个对象 BYTE 加 1 BYTE 填充。保留这个事实；也不能断言安装通用 ESI 导致了该表，因为没有证据证明主站曾写入它。

它直接证明的是 **当前 CoE 报告的映射**，不能单独证明盒子固件的最大过程数据能力。原奥太描述不默认下载 PDO 映射；若盒子字典与过程数据实现不一致，换用专用配置后 CoE 表可能仍报告原值。因此撤销“必须先联系厂家”和“必须再次读回 32 项才可继续”的前置条件，改由实际总线诊断、SM 配置及过程输入共同验证。

这仍是待实测的配置候选。仅在页面列出 32 个通道不能证明盒子已接受，OP 也不能单独证明所有应用字节已传通。

## 现场现在只做离线配置一步

1. 当前工程 **文件 → 另存为** 试配副本，例如 `WSME_32字节试配.project`，离线编辑副本。保留现场原有焊机输出程序的停用状态。
2. 用户截图已确认：“更新设备”窗口只列出 ACTI 的 LAN9252，不能按此前指引直接选到奥太。关闭该窗口；仅在离线试配副本中，先记录原从站地址、顺序及 I/O 绑定，删除对应的 `LAN9252_EVB_SPI` 从站节点，再右键原 EtherCAT 主站 **添加设备 → Aotai Electric Co., LTD → ATR-GW-EC-WSM**，放在相同物理位置，核对原地址 1001。主站、其他从站及现场原工程保留，不增加第二个物理盒子。
3. 若库中没有该项，安装原文件 `docs/工程文件/01_各设备的ethercat描述性文件/LAN9252-EVB-SPIXML-103_WSM_DZ.xml`。本机已查到安装项，通常无需重复导入。
4. 打开 **过程数据/高级过程数据**，核对 Rx 0x1601、Tx 0x1A00，各 32 个 BYTE、256 bit，子项 :01..:20。高级页“PDO 配置”“PDO 分配”保持未勾选，沿用固定配置方式；不添加 SDO 写入把条目数强改为 32。
5. 先核对这一页与 I/O 映射，不下载、不强制输出、不恢复控制调用。替换节点需重新核对绑定，不能假设自动保留。手动添加只准备主站配置，不会改变硬件身份或固件能力。当前两个描述文件不仅名称不同：Vendor 为 9 / 0x777、每方向过程数据为 16 / 32 字节，而 ProductCode=0x9252、Revision=1 相同。因此专用文件仍是试配候选，不能仅凭同协议、同产品码或添加成功认定适配。若界面或目标类型不同，先依据实际界面定位，不改 XML 身份、EEPROM 或全关检查来绕过。

## 配置核对后的实测顺序

- **身份与总线：** 在停焊维护条件下安排试配。专用 ESI Vendor=0x777，通用 ESI=9，当前 CoE Vendor=8；SII 身份尚未读出，三者不能混用。若身份不匹配，先读取实际/预期值和具体诊断，不预先硬改 XML 或关闭检查。
- **过程数据：** 核对实际状态、AL 状态码及主站过程数据诊断，必要时读取实际 SM2/SM3 长度，不能只看离线默认值。若长度被拒绝，按 Invalid Output/Input Configuration 等实际诊断定位。CoE 仍为 16 项本身不作为失败结论。
- **只读反馈：** 优先复用 `GVL_Welders.g_byWeldInMap01..32` 和原解码，结合面板可重复观察的状态、参数核对。未起弧时电流/电压为零不单独说明链路失败，尾部恒零也不能证明尾部传通。此阶段不要求接焊枪。
- **恢复控制：** 通过通信及反馈核对后，再验证具体命令、本机量程与选件。`xMappingConfirmed/xPdoOperational/xWeldPermit` 按证据放行，不写死 TRUE。起弧、检气等工艺输出不混入通信诊断。
