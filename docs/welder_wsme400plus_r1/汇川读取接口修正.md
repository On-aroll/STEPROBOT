现场最新两张截图仍是 `uiError=10`，失败对象为 `0x1018:01`，原生 `Busy/Done/Error` 三项观测均为 FALSE。此前初始化修改没有消除超时。在线 CoE 能读出厂商 ID=8，因此继续检查 PLC 程序调用路径；尚不能把超时归因于焊机型号、接线或 ESI。

本机 InoProShop 工具箱将 EtherCAT 从站 SDO 读取关联到 **CmpHCCom.ETC_COE_SdoRead**。其安装库自带文档已确认参数、默认命名空间和缓冲区接口，核对依据见 [库接口核对](reference/CmpHCCom_1.1.1.0_接口核对.md)。现在交付的完整程序及两个粘贴片段均已切换到此接口；实际通信结果仍需现场验证。

## 现场按此顺序操作

1. 保存当前工程副本，按现有流程进入可编辑状态。
2. 双击 Application 下的「库管理器」→「添加库」，搜索 `CmpHCCom`，选择 **Inovance、1.1.1.0**。如果简略视图看不到版本，切换高级视图查看。核对默认命名空间为 `CmpHCCom`，且依赖库均已正常解析。现有 `IODrvEtherCAT` 引用保留，错误类型仍使用其 `IoDrvEthercatLib` 命名空间。
3. 打开现有 `PRG_WsmeProbe`。上方声明区全文替换为 [declaration.txt](plc/PRG_WsmeProbe/declaration.txt)，下方实现区全文替换为 [implementation.txt](plc/PRG_WsmeProbe/implementation.txt)。两个区域必须同时更新。
4. 「构建应用程序」，确认 0 错误。无需新增 PROGRAM 或重复添加任务调用。此库标有 `inhibit_onlinechange`；现场按工程既有完整下载流程处理，不把它作为在线修改强行应用。
5. 现场操作者完成下载、登录后，确认 `usiMaster=1`、`uiSlaveAddress=1001`、`xAbort=FALSE`。用「写入值」使 `xStart` 经过 FALSE → TRUE → FALSE，读取一次。
6. 若 `xDone=TRUE`，记录 PDO 索引、数量、完整映射数组和字节总数。若失败，记录 `uiError`、`wErrorIndex/byErrorSubIndex`、三个 `xRead…Seen`、`eLastReadError`、`udiLastSdoAbortCode`、`udiLastDataRead`。SDO Abort Code 建议切为十六进制显示。

本次只修改诊断程序及其说明。未操作现场工程、PLC 下载或焊机输出。

## 代码改动

```iecst
fbRead : CmpHCCom.ETC_COE_SdoRead;
abyReadData : ARRAY[0..3] OF BYTE;
```

读取调用传入长期有效的 `ReadBuffer := abyReadData` 和容量 `szSize := 4`，用 `szDataRead` 核对返回长度；1、2、4 字节对象分别按实际长度解码。`byAddressMode` 使用安装库声明的默认值 0，`usiCom=1` 与现场从站地址 1001 保持一致。当前库文档没有解释其他寻址模式，程序不自动轮换模式或地址。

本版本不再访问旧读取块的 `abyData` 或 `usiDataLength`，也没有 `usiChannel` 参数。`abyReadData[0..3]` 是本程序自己声明的接收数组，与旧库的 `abyData[1..4]` 是不同接口。新增的原始中止码和返回长度会在结束后保留，便于诊断。

22 项离线状态机执行测试通过，覆盖接收缓冲区、短数据解码、SDO 中止码保留、长度异常、超时、映射复核及原有流程。测试模拟原生库，不代表 IEC 编译或实机通过。本机 InoProShop 要求管理员权限，自动查看/离线脚本未能取得编译结果；本次接口依据来自已安装库的内置帮助，而非猜测函数签名。
