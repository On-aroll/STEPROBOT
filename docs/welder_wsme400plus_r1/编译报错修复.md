## 后续仅剩 1 项 C0049：abyData 下标范围

现场最新截图显示库为 `IODrvEtherCAT 3.5.11.71`、命名空间为 `IoDrvEthercatLib`。新错误明确指出 `fbRead.abyData` 的合法范围是 **1 到 4**。此前离线模拟错误地把外部库数组设为 0 到 3，未发现该 ABI 差异，现已修正程序和模拟。

四个字节必须整体由 `[0],[1],[2],[3]` 改成 `[1],[2],[3],[4]`，不能只把第一处 `[0]` 改为 `[1]`，否则会读重或错位。正确片段为：

```iecst
udiValue := BYTE_TO_UDINT(fbRead.abyData[1]);
IF uiExpectedLength >= 2 THEN
    udiValue := udiValue OR SHL(BYTE_TO_UDINT(fbRead.abyData[2]),8);
END_IF;
IF uiExpectedLength = 4 THEN
    udiValue := udiValue OR SHL(BYTE_TO_UDINT(fbRead.abyData[3]),16)
        OR SHL(BYTE_TO_UDINT(fbRead.abyData[4]),24);
END_IF;
```

声明区未变。直接全文替换最新版 [implementation.txt](plc/PRG_WsmeProbe/implementation.txt) 即可。20 项离线测试通过，模拟数组严格拒绝 0/5，并验证 4 个不同字节及短响应长度；现场再次编译结果待确认。

截图的 MainTask 中仍有旧 `PRG_WelderBridge` 调用，它内部还会调用旧 `PRG_WelderIo` 写 PDO。诊断阶段按 [PLC 布置与下一步](PLC布置与下一步.md) 停用这条旧焊机任务调用，不能仅凭新读取程序只读就判断整个工程没有旧输出逻辑。

## 改动依据

库显示名为 `IODrvEtherCAT`，但本机安装库 `3.5.11.66` 的 `projectinfo` 中 `DefaultNamespace` 为 **`IoDrvEthercatLib`**。其 `browsercache` 同时列出了 `ETC_CO_ERROR` 和 `ETC_CO_SdoRead4`。因此原先 `IODrvEtherCAT.` 的代码前缀错误，修正为：

```iecst
eLastReadError : IoDrvEthercatLib.ETC_CO_ERROR;
fbRead : IoDrvEthercatLib.ETC_CO_SdoRead4;
```

实现区的枚举常量前缀也已同步修正。不是把真实 SDO 功能块删掉，也不需要给 `fbRead` 自动声明成普通数值变量。

现场编译器在 `DIV` 处报 C0189/C0009；之后 `uiTxBytes` 和 `xRxByteAligned` 的错误是语法分析连锁结果，不能据此认定这些变量未声明，也不能据此断言 MOD 本身不受支持。为避免该处整数除法兼容问题，统一采用 WORD 位运算：

```iecst
uiRxBytes := WORD_TO_UINT(SHR(UINT_TO_WORD(uiRxBits + UINT#7),3));
uiTxBytes := WORD_TO_UINT(SHR(UINT_TO_WORD(uiTxBits + UINT#7),3));
xRxByteAligned := (UINT_TO_WORD(uiRxBits) AND WORD#7) = WORD#0;
xTxByteAligned := (UINT_TO_WORD(uiTxBits) AND WORD#7) = WORD#0;
```

每个方向最多 32 项，每项位宽不超过 255，总位数不超过 8160，加 7 不会溢出 WORD。右移 3 位实现向上取整的字节数，低 3 位全零表示按字节对齐。当前 20 项离线测试已通过，包括最大条目位宽、空映射、非字节对齐及库的 1 起始数组；尚未取得最新修正后现场 InoProShop 构建结果。

## 如果修正后仍报未知类型

这时继续检查工程库引用，不改硬件连线：

1. 在 `Application` 下双击「库管理器」，查看 `IODrvEtherCAT`（显示大小写可能略不同）是否已列出并正常解析，不能处于缺失/未解析状态。
2. 查看该库实际命名空间。若工程自定义过命名空间，以当前工程值为准；可在声明处按 F2 打开输入助手，从库中选择 `ETC_CO_SdoRead4`，让编辑器插入实际类型前缀。
3. 若库未直接引用，使用库管理器「添加库」搜索 `IODrvEtherCAT`，优先使用当前 EtherCAT 设备包指定/已解析的同一版本，不盲目切换到最新版本。若只有未解析占位符，先核对其解析到的实际库和版本。
4. 保存新的错误文本及库管理器信息继续核对，不删除真实读取调用来消除报错。
