## 1. 这个目录是什么

不是代码工程，而是**上海新时达（STEP）工业机器人的官方资料包**——一台机械臂 + 控制器 + SPad 示教器 + 上位机 SDK 的完整开发生态文档。目录里 7 个文件的角色：

| 文件 | 角色 | 定位 |
|---|---|---|

| `STEP机器人用户编程手册-1.8.1` | **机器人脚本语言指令字典**（138 页） | 数据类型 + 运动/流程/IO/中断语句，查阅为主 |

### 1.2 检索这批文本时的两个已知失真

- **表格和公式被拆散了**：PDF 里的表格/公式不是丢失，而是被转成"一行一个符号"。例：动力学 3.4.1 的圆柱体主惯量矩在文本里长这样——`𝐽𝑥𝑥` / `=` / `𝑚 12` / `(𝑏2` / `+` / `𝑐2)`，分式与上下标全丢。**数值都还在，结构没了**；凡是要抄公式或抄寄存器地址表，必须回原 PDF（`STEPStudio 4.7.0\help documentation\`）。
- **编码**：这批 `.txt` 是 UTF-8 无 BOM，但 `_extract/sdk/` 下的厂商头文件是 **GBK**，两者混在一次 grep 里时中文会花。`动力学.txt` 转出来时曾有 27 行是非法 UTF-8（数学斜体符号被写成 CESU-8 代理对），2026-09-26 已无损修复，公式里的 `𝐽 𝑥 𝑚 𝑏 𝑐` 现在能正常显示和检索。

## 2. 先建立心智模型：四层结构 + 三条通讯路线

```
第④层 上位机 PC（SDK / 自研算法）      ← 你做研究主要待这一层
        │ TCP/IP 客户端 → 控制器:30312
第③层 机器人控制器（实时内核 + HMI）
        │ ①SDK 命令   ②Socket:8889   ③Modbus:502(RTU/TCP)
第②层 SPad 示教器（写/调脚本、标定工具与坐标系、看报警）
        │ 解释执行
第①层 机器人脚本程序（.sr 工程 / .srp 程序 / .srd 变量数据）
        │ 运动学 + 伺服
第⓪层 机械臂本体（6 轴 + 可选附加轴）+ 工具 TCP + IO/夹爪/焊机
```

三条外部通讯路线，端口和角色都是查实的：

| 路线 | 端口 | 机器人角色 | 能干什么 | 不能干什么 |
|---|---|---|---|---|
| **SDK（C++/C#）** | **30312 固定不可改** | 服务端，**同时只允许 1 个客户端** | 上/下使能、切模式、加载程序、读写任意脚本变量、DI/DO/AI/AO 强制与仿真、点动到指定位姿、用"语句流"当场下发一段运动程序 | 不与示教器之外的第二台 PC 共用；文档未提供 disconnect 接口 |
| **示教器 Socket** | 服务器模式固定 **8889**；客户端模式自定义 1024-65535 | 服务端/客户端都行，只支持 TCP | 在机器人脚本里收发字符串/字节/整数/实数/位姿 → 接相机做视觉引导抓放 | IP 必须与机器人同 `192.168.39.*` 网段；单帧 ≤511 字符 |
| **Modbus** | TCP 默认 **502**（可改），或 RTU 串口 | **只能做从站**，且 RTU 与 TCP 不能同时开 | 上位机/PLC 通过寄存器读写机器人 IO（映射到通用 IO 端口，可监视 32 个 WORD） | 不能下发位姿、不能控制程序运行；寄存器↔端口对应表只在 PDF 截图里，正文没有 |

**结论：搞算法研究走 SDK；机器人自己要当主控（读相机）走 Socket；只要握手信号走 Modbus。**

## 3. 该读什么：四遍读法（预计 3～4 天，不要通读）

这些手册加起来 570+ 页，通读必死。按"能跑起来 → 能控制 → 能改轨迹 → 能对接设备"四遍走，每遍只读必要章节。

> 下面提到的 `SPad 操作软件说明书`、`用户编程手册`，**一律读 `_extract/studio_txt/` 里 V1.8.1.20241015 那两份**（比根目录的 20240516 新一版，见 §1.1）；Studio 包里没带的才回 `_extract/txt/`。

### 第 0 遍 · 保命 + 打通链路（半天，不可跳过）
读 `SPad 操作软件说明书`：
- **第 1 章 前言**、**第 2 章 安全**（2.1 全部）：急停按钮在示教面板上、按下后驱动器立刻关断；运行方式只有 **T2（手动，点动最高 250mm/s）/ AUT（自动）/ AUT EXT（外部自动，用于有上层控制系统时——你做 SDK 研究就是这个模式）**；机械终端限位 A1/A2/A3/A5/A6；软件限位只作机械防护；运动中途切换运行方式会立刻中断。
- **3.3 登录 / 3.12.6 IP**：确认控制器 IP 与 PC 同网段。
- 然后**动手**：把 PC 网线直连控制器，设 PC 静态 IP `192.168.39.x`，`Test-NetConnection 192.168.39.220 -Port 30312`。

### 第 1 遍 · 会开机器人、会示教一段轨迹（1 天）
读 `SPad 操作软件说明书`：
- **3.4 工具和坐标系示教**（3.4.1 工具示教、3.4.3 坐标系示教）——**这是所有研究的前提**，TCP 标错了后面全错。
- **4.1 点动运行**（连续/增量/位置点动/程序点动/多轴点动）、**4.2 自动运行**、**4.3 程序运行模式**、**4.4 操作模式**。
- 顺带记住 **3.10 回零设置**：默认回零密码 **123**；文档明确写了"回零会影响之前编写的所有程序位置点"，**研究期间绝对不要动回零**。
- 练手目标：在示教器上新建工程 → 示教 4~6 个点 → `PTP/Lin` 混跑 → 连续/单步两种模式各跑一遍。

### 第 2 遍 · 看懂机器人脚本（半天精读 + 长期查阅）
读 `用户编程手册`，它其实就是一本指令字典，只有 3 章：
- 必读顺序：**1.3 文件架构 → 2.1 基本数据类型 → 2.2 位置类型 → 2.3 坐标系/工具 → 2.4 动态与圆滑 → 3.1 运动语句 → 3.2 设置语句 → 3.5 流程 → 3.6 IO → 3.7 中断**。
- 查阅型：3.4 数学语句（60 条）、3.8 外部量（与 PLC 交互）。
- 语言要点（实测自手册）：语句形如 `类型 名 := 值;`，注释用 `#`；**运动指令是 `PTP / Lin / Circ / CircleAngle / PTPRel / LinRel / Spline / LinISR / PathRec*`，注意：全篇没有 MOVJ/MOVL/MOVC**；统一形参 `(pos, dyn, ovl, ori, tool, refsys)`，只有位置必填；**速度不写在运动行里**，而由 `DYNAMIC`（12 个量：PathVel/Acc/Dec/Jerk 用 mm/s，OriVel 用 deg/s，JointVel 用 %）或 `JointVel()/CartVel()/Override()` 设置；**逼近区= 圆滑 Ovl**（相对 0~100%，越大越早离开示教点，只有 0 才真正到点），不用时取机器人配置文件默认值——研究轨迹精度时这是第一大误差源。

### 第 3 遍 · 用 SDK 把机器人接到你的程序里（1.5 天）
读 `SDK使用说明-CSharp`（C++ 接口名与之一一对应，`RobotCom.hpp` 可直接对照）：
- 必读：**1 使用前准备 → 2.1 通讯 → 2.2 状态反馈（25 个只读接口）→ 2.3 基础命令（使能/模式/加载/清错）→ 2.4 参数设置 → 2.8 语句控制接口 → 3 两个完整案例**。
- 只读一遍就够、需要时再查：**2.5 变量设置（74 小节）+ 2.6 变量获取（40 小节）**。三套命名规律吃透即可：`VariableXxxModifyCmd`（改，程序须停止）、`ProcessVariableXxxModifyCmd`（在线改，受程序预读影响）、`VariableXxxReadCmd`（读）。全局变量固定用工程名 `_global`、程序名 `_project`。
- **可整体跳过**（除非你做焊接/折弯/打磨/码垛）：2.5 与 2.6 里 Arc/Weave/CD/CDS/PAT/Track/Laser 全部小节、2.8.12~2.8.16 焊接语句、2.7.3~2.7.4 焊接应用。基础运动控制用不到。
- 文档要求：控制器软件 **V1.8.0.20240531_0712 及以上**；C# 侧 VS2022 + .NET7.0，库是 Release x86/x64。

### 第 4 遍 · 需要外部设备时才读
- 相机/视觉引导：`Socket 功能说明书`（重点：Socket 变量**只能是全局变量**；`SocketOpen/SocketSendString/SocketRecvPos/SocketSetting`；`Open` 要放进循环里重试直到返回 TRUE；不设 `SocketSetting` 时 `Recv` 默认非阻塞且只执行一次；控制器是**小端字节序**，发 `3.14` 要发 `1F 85 EB 51 B8 1E 09 40`）。
- PLC 对接：`Modbus 通讯说明书` 第 3/4 章（RTU/TCP 二选一；总线配置保存后**必须点重置或重启控制器**才生效；地址表要回 PDF 看截图，正文没有）。

### 第 5 遍 · 工艺侧（WAAM 方向，等资料里那 4 遍走完再读）

新时达**没有给你任何增材工艺文档**（§1.1 结论 1），所以这一遍是"借焊接的语义搭自己的沉积模型"，只读三份、别多读：

1. `焊接-V1.8.1.20240929`：只读"多层多道"那 12 处所在的章节 + TIG/脉冲参数设置。你要的是它对**道与层的组织方式、跨段参数切换、清枪/退丝**这类流程语义。
2. `线激光焊接功能_V1.8.1.20240516`：**这份才是你逐道修正的原型**。它是"传感器拿到轮廓 → 实时纠偏焊接路径"的完整链路，与"上一层凝了多高 → 下一道 Z 补偿"是同构问题。
3. `动力学-V1.8.0.20230602`：读法与全部数值见 **§4.1~4.3**。重点 3.3/3.4 负载与惯量（沉积层+工件+夹具会改变末端负载）、3.7 碰撞检测、5.2 避奇异（全库"奇异"命中 56 次，多层堆叠到高位时这是真问题）。

### 4.1 负载与惯量（《动力学》V1.8.0.20230602，原 PDF 第 12-22 页）

入口：**菜单 > 高级功能/功能包 > 动力学**。界面共七块：基本设定、负载辨识、本体负载、振动抑制、前馈补偿、拖动示教、碰撞检测。**基本设定需密码，文档明示联系售后**（里面是安装方式与摩擦力辨识）。

| 项 | 值 |
|---|---|
| 一套负载动力学参数 = 10 个量 | 质量 m；质心 x/y/z；转动惯量 Ixx/Iyy/Izz/Ixy/Ixz/Iyz |
| 末端负载分两种 | `toolload`（工具）与 `payload`（工件），**都可辨识**；本体负载**不能辨识，只能手填** |

### 4.3 运动学改进：变惯量 / 避奇异 / 绝对圆滑（第 36-41 页）

| 项 | 实测值 |
|---|---|
| 变惯量怎么开 | `DYN` 的关节加速度/减速度/加加速度**范围由 0-100 改为 0-200**；三者**都 >100** 才激活力矩计算＝开启变惯量；实际加速度＝力矩算出的 acc×(dyn里的加速度-100)/100（减速度、加加速度同理） |
| **速度曲线会被改写** | 力矩计算加减速时**把 sin 型速度曲线换成 s 型**（5.5 第 1 条）→ 对普通搬运是优化，对沉积是**热输入剖面变了**。做多层多道必须显式记录这个功能的开/关状态 |
| 避奇异 | 笛卡尔路径经过轴 5 奇异位姿时，把姿态插补方式选 `eWRIST`（腕关节）。内部等价：`circleangle→circle`、`linerel→line`、`ptprel→ptp`；间断焊中腕关节插补会被直接改成 `evar` |
| 奇异区间提前报错的阈值 | 五轴：4 轴加速度>1000 且 5 轴在 ±20° 内、朝 0° 运动；二三轴：3 轴加速度>500 且 3 轴在 [-110°, -70°]、朝伸直方向(-90°)；一轴：1 轴加速度>100 且 腕关节 xy 距 base 原点 <100 mm、朝原点运动 |
| 姿态速度与前瞻 | 内部对姿态速度/加速度/加加速度 **×3**，上限 400 / 1200 / 12000（点动时不改）；路径前瞻**最多提前 10 条**；超速点预判不能 100% 排除超速 |
| 绝对圆滑 | `Ovl` 新增类型 `OVERLAPABS`（也可选固定档）。优势在路径短、速度不高、要求速度平稳；**不适用于**电弧跟踪、激光跟踪、独立轴、固定工具、带附加轴——**内部自动转成相对圆滑**，属静默降级 |
| 不支持变惯量（仍按原规划走） | 寻位、折弯同步、矫正、**所有跟踪**、BendsynMove_IO、BendTrack_IO、LinISR、折弯语句、**任何带附加轴的情况**、避奇异路径 |
| 腕关节插补的限制 | 不支持力矩加减速；不支持激光跟踪/电弧跟踪/摆弧/流水线跟踪/变位机坐标系/四轴机型/固定工具/导轨。**不经过轴 5 奇异时不要用它**——就近选解会让末端姿态与示教姿态不同 |
| 相关码（去 931 条那份查原文） | warning **4860** 腕关节插补中模式切换；err **5107** 圆滑过程中模式改变；**2506** 圆滑过程模式切换 |

## 7. 已知坑（文档原文 + 文档自身笔误）

**行为类：**
- 返回 `0` 不等于动作完成，**必须回读状态确认**；卸载示教器程序返回 0 只代表"正在卸载"，卸载模拟程序返回 0 才是完成。
- `ProgramLoadCmd` 失败返回错误行号，**行号 -1 表示错误很多，得去示教器看**。加载程序前提是"当前无程序加载"。
- 改普通变量要求**示教器程序处于非运行状态**；在线改只能走 `ProcessVariable…`，且受**程序预读**影响可能"改了没生效"（`Pause`、`EXIT`、`ReturnMain` 都会重置预读/变量初值）。
- 取消 DI 强制的 `DigitalInputSimulationRemovalCmd` **会复位 DI**；取消 DO/AO 强制不改当前状态——两类语义不同，别混。
- `OverrideSetCmd` 范围 0.1~100，>1 时会被四舍五入成整数（即精度只有 1%）。
- 点动必须在**手动模式**；绝对点动结束要 `JogToPositionExitCmd` 退出，否则后续示教被占。
- 中文错误信息有编码问题：V1.2 修订记录专门写了"修复错误信息获取乱码"，示例里还先 `Encoding.Default` 再 `Encoding.UTF8` 二次转码——自己封装时统一处理。
- `SaveData`/`RecordList` 高频写会伤存储，`RecordList` 必须放程序第一行、最多 10 个变量。
- `Spline` 至少 3 段且不能出现往返点；`AuxSystem1ToRoot`、`AxisRatioConfig` 改的值**断电后复位回标定值**。

**文档笔误（照抄会编译失败/调错函数），C# 说明书里已核出的：** 2.2.10 返回类型写成 `CartDynState` 实为 `SubDynamic`；AXISPOS 字段表写 `m_AuxPos` 但示例用 `m_AuxJoint`；2.5.34 标题 `VariableCDDataModifyCmd` 示例调的是 `VariableCDModifyCmd`；2.6.4 读 REAL 的示例误调 `VariableIntReadCmd`；2.8.11/2.8.16 小节标题函数名与示例不符；2.8.3/2.8.4 示例里有循环外的 `continue`。→ **一律以 `_extract/sdk/.../RobotCom.hpp` 的声明为准。**

**SDK 文档完全没有的内容：** 安全章节、报警代码表、网络异常重连策略、断开接口。
→ **报警代码表这一项已经补齐**（2026-09-26）：`_extract/studio_txt/错误详细描述20240906.txt`，931 条，每条按"故障描述 / 故障原因 / 排查方法 / 解决方案"四段写；控制柜自带的 418 个 htm 覆盖不到它的一半，两者关系见 §4 速查表。安全章节去 SPad 说明书第 2 章。**重连策略与断开接口仍然没有任何文档**，只能实测。

## 8. 可以往哪些方向做研究

  通了 → 你的 C++ SDK 代码可以**零改动**对着虚拟控制器跑，A/C 两条线合成一条；不通 → 虚拟控制器只对 Studio 自己的界面服务，SDK 侧仍必须有真机，那就老老实实按 C 线自建仿真。**在实测之前不要按"能通"来设计研究方案。**
- 激活：超过试用期需【帮助】→"导出激活信息"发新时达换授权文件。**Win11 默认关闭 WMIC 会导致"导出失败"**，需在"设置>系统>可选功能"装 WMIC，并确认 PATH 里有 `C:\Windows\System32\Wbem`；机器人名录页面只标"多关节工业机器人"，无型号清单——你机型在不在库里，得实机打开机器人库看（或打 400-821-2527）。

**B 线 · 真机上的"零风险半实物仿真"：控制器轴虚拟功能（被严重低估）**
SPad 说明书 3.11.1 通用配置 → **轴虚拟**："可以在线来回切换实际轴和虚拟轴"；操作是勾选要虚拟的轴 → **在断使能状态下点保存** → 成功后示教器状态栏显示"轴虚拟"。
含义：被虚拟的轴不再驱动真实电机，但控制器仍然按指令计算其位置、程序照常解释执行 → **可以在真机上做"不动臂"的程序逻辑/节拍验证**。配合 `OverrideSetCmd(10%)` + DI 仿真 + DO 强制，能覆盖"先把逻辑跑通"的绝大多数需求。
- 注意：**控制器重启后不保留轴虚拟设置**（原文写明），每次开机要重设；且只虚拟部分轴时**其余轴照样会真动**，安全不能省。
- 顺带：回零会影响所有已示教点位（3.10，默认回零密码 123），研究期间不要碰。

**C 线 · 自建可编程仿真（研究的长期基础设施，也是我们真正能发论文/做算法的地方）**
建模数据来源都是现成的：
- **DH 参数**：入口是 SPad **3.11.3 机器人 DH 模型参数配置**（新版第 132 页；操作路径 STEP>参数配置>系统功能>通用配置>**DH 参数按钮**，配的是"连杆参数"）；SDK 侧对应 `RobotDHParam{m_JointType(eLinear/eRotary), m_Alpha 连杆转角, m_A 公垂线长度, m_D 连杆偏距, m_Theta 关节角}`，命令字 `eDHParamSet = 204`。
  ⚠️ **通用手册里不存在你机型的 DH 数值**——41 份文本里 `DH参数` 命中 0 次，SPad 那一节只有界面截图（截图抽不出来）。数值只能从**真机示教器界面读**，或用 `eDHParamSet` 那条命令向控制器要。别在文档里找，找不到。
- **软限位 / 耦合比**：3.5.2 关节空间设置、**3.11.4 机器人轴耦合比配置**（133 页）、**3.11.5 四轴限位配置**（134 页）。
- **负载与惯量**（动力学仿真必需）：《动力学》3.3 负载辨识、3.4 本体负载（1、2 轴参数相对**基坐标系**，3 轴相对**法兰坐标系**，转动惯量取**质心系下主惯量矩**）；4.1.1 `PAYLOAD` 变量 + 4.2.1 `PayLoad` 语句；懒得手推公式就用 Studio 4.7.0 的"负载计算"。
- **机型/序列号**：`RequestRobotInfoCmd(RobotInfoStruct&)`（字段 `m_Name`、`m_RobotSNo`）。
- **位置真值**（用来校准仿真）：`getAxisPos()`、`getCartPosWorld()/RobotBase/UserRef()`。

技术栈落地有两步，互不冲突：
1. **零安装先看几何**：单文件 HTML + Three.js 的正运动学可视化（拖 6 个关节滑块看 TCP 位姿、画轨迹、查可达域）。适合第一天就有反馈。
2. **与 C++ 主线同构**：在 C++ 里写一个 `RobotModel`（FK / IK / PTP-Lin-Circ 插补 / `DYNAMIC` 12 量 / `Ovl` 圆滑语义），并定义一个后端接口 `IRobotBackend`，两个实现：`SimBackend`（自己算）和 `SdkBackend`（真机 `RobotComClient`）。**研究代码只面向接口写**，仿真迭代完了把后端一行切到真机，这就是"仿真→真机"最省事的迁移结构。

第三方通用软件（RoboDK、CoppeliaSim、Gazebo/ROS2）也可行，但都需要机器人的 URDF/STEP 三维模型，新时达没有公开发布 → 要么自己按 DH 建（与 C 线复用），要么找厂商要模型；RoboDK 侧有 [URDF 导入插件](https://robodk.com/addin/com.robodk.app.importurdf) 可用。

### 9.3 仿真先行的落地顺序（建议）

1. **确认机型**（示教器 3.15 系统信息 / 机身铭牌）→ 决定 STEP Studio 机器人库里有没有它、决定 DH 参数。
2. **打开已装好的 Studio，导入机型，启动虚拟控制器**：跑一遍可达性 + 节拍演示（半天出结果）；**同时**做 §9.2 A 线那个 `127.0.0.1:30312` 实测——这一步决定后面所有仿真代码要不要写 `IRobotBackend` 之外的东西，**必须最先做**。
3. **装 VS2022 + C++ 桌面开发**（真机 SDK 与自建仿真都要它，早装不吃亏）。
4. **搭 C 线最小仿真**，然后做**校准**：让仿真算出的 `XYZABC` 与示教器"位置监视"界面 / `getCartPosWorld()` 的读数对上（同一组关节角，误差应在 0.1mm 量级）。**没做这一步校准之前，仿真结果一律不可信。**
5. 在仿真里把研究变量铺开：`PTP/Lin/Circ/Spline` 混跑、`Ovl` 圆滑 0~100 对轨迹的影响、`DYNAMIC` 各档速度曲线——这些在真机上做成本高、在仿真里做几乎免费。
6. 真机只做抽样验证 + 回归测试：先用 **B 线（轴虚拟 + 10% 倍率 + IO 仿真）** 验逻辑，再实动。
