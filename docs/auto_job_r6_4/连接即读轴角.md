# 连接PLC即显示六轴，运行时持续更新

安装后流程是：连接PLC → 自动读取实际J1～J6 → 三个页面更新模型。无需进入微调、登记控制会话或加载10号。运行中继续读取实际轴角；已固定的预览起点与终点虚影不会跟随机器人漂移。数据超过1.5秒失效时保留上一姿态并标记过期。

厂家《ModbusTCP-1.8.1版本使用说明V2.3》第11页列出30065～30076为六个REAL关节坐标；Modbus报文使用 **FC04、起始偏移64、12个WORD**。PLC独立只读连接使用现有机器人LAN B地址和502端口，暂停100ms后发起下一轮读取。实际刷新间隔还包括PLC扫描和网络时间。无需SDK，也不需要修改已有控制/FTP读写通道。

## 现场按此顺序安装

1. 将当前能上传成功的PLC工程另存副本。确认 **MW500～539** 在现场未被其他变量占用；本工作区已交付的R6.3/R6.4映射没有使用这一段。确认 `CmpHCTCPIP` 连接ID **244** 未被现场其他代码使用；FTP已使用245、246，本次单独使用244。
2. 新建**全局变量表GVL**，名称 `GVL_RobotJoints`，粘贴 `plc/GVL_RobotJoints.st` 的全文。`aStatus` 必须保留 `VAR_GLOBAL PERSISTENT RETAIN` 两个属性；程序每扫描重建状态，不信任残留有效位。
3. 在GVL中将 `sRobotAddress` 设置为**控制柜机器人LAN B地址**，应与现有 `FB_FileFtp.stControlServer.strIPAddr` 完全一致。默认 `192.168.3.188`；这不是上位机连接的PLC LAN A `192.168.1.188`。端口默认502、Unit默认1。`xEnable=TRUE` 表示持续只读取数。
4. 新建**功能块FB**，名称 `FB_RobotJointRead`，语言ST；上方声明区替换为 `plc/FB_RobotJointRead/declaration.txt`，下方实现区替换为同目录 `implementation.txt`。它复用本次FTP提速已经安装的 `FB_FileSocketIo`、`CmpHCTCPIP`、`SysSocket`、`CmpErrors`，不需要新增库。FB本身不要单独加到任务。
5. 新建**程序PRG**，名称 `PRG_RobotJoints`，语言ST；分别替换 `plc/PRG_RobotJoints/declaration.txt` 与 `implementation.txt`。在现有循环任务中，放在机器人状态已更新之后，**每扫描执行一次**。例如现有RobotBridge→ManualBridge→FileBridge顺序保持，再调用RobotJoints；不要重复调用，也不改原有参数写入位置。
6. 在InoProShop构建到0错误，然后由现场操作者下载。此新增代码已通过本地ST解释执行和上位机模拟通讯测试，尚未由本机在现场InoProShop编译或对真实控制柜取数。控制柜固件也须支持厂家列出的扩展寄存器。
7. 关闭旧上位机窗口，再运行本目录 **启动上位机R6.4候选版.cmd**。新窗口标题为 **R6.4 实时姿态版**。连接PLC后应直接出现“有效 · PLC 六轴反馈”，不用点③进入微调。先逐轴对照示教器J1～J6数值，再观察三个页面的模型是否一致。

第一次比对发现所有数值明显错误时，保留原始WORD核对顺序：本版默认第一寄存器为REAL低半字；仅在已确认控制柜实际为高半字在前时，才将 `xHighWordFirst=TRUE`。不能自动猜测字序或用全零替代无效数据。

## 在线检查位置

`PRG_RobotJoints.fbRead` 提供 `uiStep / xValid / xError / wErrorID / uiAgeMs / udiCounter`。计数器在每次完整、匹配事务的FC04应答后增加，即使机器人静止不变也会增加。只有完整应答才更新12个WORD，不发布半包。

上位机只读PLC **HR500～539**。HR500应为 `16#4A52`，HR501为1；HR502的bit0是有效、bit1是停止、bit3是机器人在线。正常停止时为11，运动时为9。HR506～507是数据计数器，HR508是数据年龄ms，HR510～521是归一化为低字在前的六个REAL；HR532～533重复计数器用于识别混合帧。HR535是错误码，HR536应为 `16#0641`。

错误码A101=发送/发送超时；A102=接收/应答超时；A103=超长应答；A104=事务号、协议号、Unit、功能码、长度或异常应答不符合预期；A105=套接字关闭失败。普通通讯错误关闭连接后等待1秒重试；关闭失败保持占用并停止使用ID244，现场确认连接资源后再重新初始化此功能块。

旧PLC没有新增区时，上位机会兼容读取原HR450～489手动快照，并显示持续轴角尚未接通；不会为了得到姿态自动进入微调。新通道只提供六轴，未伪造TCP坐标，也不据此宣称已到达工艺终点。模型轴向与零位仍须和现场本体对照校准。

## 同时修复的自动作业显示

转换窗口关闭后，主界面左侧切换为此次生成的 `auto_main` 和连续的 `auto_XX`，保持上传的原始字节和版本号。选择轨迹程序时更新对应路径，并显示原G代码文件名。仅转换、上传失败和上传成功各有不同提示。补丁可查看，不能当作包含实验起点的完整新工程上传或编辑版本检查。

11号继续绑定 `pcjob_manual_r63.sr / auto_main`。生成的 `AutoJobPatch.zip` 是对该工程的更新，不是另一个待绑定工程。示教器新建时只有EOF正常；上传后应重新打开原工程里的入口，核对版本检查和 `ProgCall(auto_01);` 等调用。如果重新打开仍只有EOF，需要继续核对柜内路径与同名重载；FTP成功不等于解释器已经更新。
