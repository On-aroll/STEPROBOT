# R6.4 自动作业候选版

**3736入口语法修复已加入：使用窗口标题带“入口修正版”的上位机，重新导入G代码生成并上传。此次无需修改PLC。具体步骤见 [3736入口修复.md](3736入口修复.md)。打印方向保持捕捉起点时的末端方向，允许J5/J6协调运动。**

本版从 R6.3 接回自动作业：导入 G 代码 → 自动转换 → 选择 **PLC 批量转传** 或 **电脑直传（SDK 手册 FTP 方案）** → PLC 回读校验 → 显示可用作业号。随后由你点击登记、加载、确认加载、使能、运行。两种传输方式的现场比较见 [电脑直传对比.md](电脑直传对比.md)。

这次复用一个固定入口：**11号 → `pcjob_manual_r63.sr / auto_main`**。一个作业可包含1～15个轨迹程序，入口按清单顺序调用，不再固定三个程序。15是当前32文件传输容量扣除入口后的上限。

手动仍使用10号 `manual_service`，速度、目标移动、捕捉起点、返回起点沿用R6.3。自动轨迹读取同一工程里的 `msHomeCart / msHomeSaved / msOrigin`。**日常上传不写 `_project.srd`、`manual_service.srp/srd`，也不重新捕捉起点。**

本目录是独立候选版。现场已确认基础R6.4上传和回读成功：2026-11-18的一次66,117字节作业耗时6.463秒。本次新增的持续六轴反馈仍需在InoProShop编译安装；真实控制柜同名重载尚待确认。

**当前更新：连接PLC即读取实际J1～J6，运行中持续更新三页模型，不再依赖进入微调。安装步骤见 [连接即读轴角.md](连接即读轴角.md)。** 转换窗口关闭后，左侧也会显示本次生成的 `auto_main / auto_01…`，并明确标出本地预览及上传状态；原螺旋模板不再冒充本次自动作业。

**现场已安装基础R6.4时，FTP提速按 [传输升级安装.md](传输升级安装.md) 更新两个对象并新增两个对象；3736修复只更新上位机并重新转换。** 当前上位机已合入 [三维姿态R1的最新优化](三维姿态整合.md) 和持续六轴反馈，独立安装到 `native_plc_auto_r6_4_pose_guard_candidate`；此前候选运行目录保留。

## 一次性安装：先编译PLC

1. 将当前已验证的PLC工程另存一个副本。本次基线是当前R6.3，不能使用已暂停的旧“三程序固定覆盖”包。
2. 在现有 `GVL_FileBridge` 的普通 `VAR_GLOBAL` 中追加 `plc/01_追加到GVL_FileBridge.txt`；若已有同名变量，核对并修改，不重复声明。现有MW6000/6120/6200映射、FTP账号密码、许可条件和缓存保留。目标工程名为 `pcjob_manual_r63.sr`，手动号10，自动号11。`xFixedMappingConfirmed` 先为FALSE。
3. 在现有 `GVL_RobotBridge` 普通变量区追加 `plc/02_追加到GVL_RobotBridge.txt`。其余现场声明、保持数据及I/O映射保留。`uiFixedJobGuardVersion` 由程序发布，不手动强制。
4. 库管理器核对 `CmpHCTCPIP 1.0.0.7`，显式添加/解析 `SysSocket 3.5.9.0` 与 `CmpErrors 3.3.1.40`。批量后端调用 `CmpHCTCPIP.GetSocketInfo` 和 `SOCKET_INFO`（本机1.0.0.7库有这两个隐藏符号），再做非阻塞SysSocket收发；现场编译必须确认这两个符号可访问。本机IDE要求提权，未完成实际InoProShop编译；若版本不符或隐藏符号不可调用，保留原工程并反馈编译错误，不得删掉校验绕过。
5. 先新建三个ST函数（FUN）：`F_AutoFileIndex` 返回类型 **UINT**；`F_FixedFileValid` 返回类型 **BOOL**；新增 `F_FileCrc32Fast` 返回类型 **UDINT**。再新建功能块（FB）`FB_FileSocketIo`。分别使用同名目录的声明/实现片段。InoProShop上方声明区全选替换为 `declaration.txt`，下方实现区全选替换为 `implementation.txt`。已有 `F_FileCrc32` 和 `F_FileNameValid` 保持原实现，附本仅供核对。函数和FB都不单独加入循环任务。
6. 再替换现有 `FB_FileFtp`、`PRG_FileBridge`、`PRG_RobotBridge` 的声明区和实现区，使用 `plc/同名目录/declaration.txt` 与 `implementation.txt`。两个区域分别全选替换，避免保留旧声明。这些片段已去掉实现区尾部的 `END_PROGRAM / END_FUNCTION_BLOCK`。若IDE弹出自动声明窗口，不要把函数名声明为局部变量；尤其不能出现 `F_FixedFileValid: INT;` 或 `F_AutoFileIndex: INT;`。已有R6.4机器人桥不需重复更改；本次传输提速只更改前两个对象并新增两个对象。
7. 同一循环中依次执行 **PRG_RobotBridge → PRG_ManualBridge → PRG_FileBridge**，各一次；文件桥必须在ManualBridge清空/写入参数之后执行，并在现有 `ParamProbe_Write` 发送参数之前完成。现有机器人收发与参数通道继续使用，不增端口、不增柜内Modbus通道。
8. 编译，先取得0错误结果。本包完整GVL是参考文件，不能整份覆盖现场配置。R6.3的 `PRG_ManualBridge`、保持位置区和柜内手动服务不需要替换。批量后端每实例每扫描最多一次8192字节收发；下载后观察任务执行时间和看门狗余量，再做速度实测。

若出现 `FB_FileFtp` 调用 `F_FixedFileValid` 的 C0035/C0077，且声明区同时提示 C0181重名，检查并删除误加的局部变量 `F_FixedFileValid: INT;`，保留同名BOOL函数，再重新编译。2026-11-18现场此组5错误已定位为这条局部声明遮住函数；交付的 `FB_FileFtp/declaration.txt` 不含此声明。具体见 [编译报错修复.md](编译报错修复.md)。

## 一次性安装：新增11号入口

1. 在示教器核对10号确实为 `pcjob_manual_r63.sr / manual_service`，并确认11号空闲。当前候选版固定使用该工程和11号；如果现场不符，先调整候选配置再安装，不能覆盖其他已绑定作业。
2. 在这个**已有工程内部**新建程序 `auto_main`，初始仅有EOF也可作为一次性空占位；不需要在示教器手工输入 `ProgCall` 文本。先保存这个空入口并完成绑定。正式上传会自动替换 `auto_main.srp/srd`，同时放入 `auto_01…`。上传后退出旧编辑页再重新打开核对内容，不要把旧空白页保存回文件。不要重新导入整份R6.3工程，避免覆盖已保存的实验起点。
3. 将11号绑定到 `pcjob_manual_r63.sr / auto_main`，保存。10号原绑定保留。这一步只做一次；后续作业更新复用11号。
4. 由现场操作者应用配套PLC更新；保留原许可和FTP配置。确认工程/编号一致后，把 `GVL_FileBridge.xFixedMappingConfirmed` 本地设为TRUE并保存配置。**只在线写当前值不会修改源码初始化值**：对已经完成上述绑定核对的现场工程，将该变量的声明改为 `xFixedMappingConfirmed : BOOL := TRUE;`，保存并在机器人停止、断使能后按现场流程编译应用。首次未确认绑定的工程仍保留FALSE。`uiFixedJobGuardVersion` 必须由配套主桥发布为140，不能手动强制；`xFixedReady`、`xFixedIdle`、上传状态和版本标记继续由程序生成，不能一并改为TRUE或保持旧上传结果。初始 `xFixedReady=FALSE` 正常，完整上传后才为TRUE。
   注意区分声明初值与在线当前“值”：声明已经是 `:= TRUE` 时不要重复改同一行，在线修改可能保留旧变量值，应核对当前值、强制状态和在线应用。应用停止时，保持寄存器可能仍显示上次的配置/空闲状态；先确认循环在刷新，再判断预检条件。详见 [重启后上传预检不通过.md](重启后上传预检不通过.md)。
5. 双击本目录 **启动上位机R6.4候选版.cmd**。不要用R6.3的旧导入界面完成固定入口更新；旧文件桥没有本版能力时，新入口会在写入文件命令前拒绝。

## 传输方式选择

在自动作业上传窗口选择：

- **PLC 转传（批量提速版）**：PLC 接收每帧仍为192字节，PLC 到控制柜的 FTP 已改为8192字节批量收发，并保留完整回读校验。
- **电脑直传（SDK手册FTP方案）＋ PLC回读校验**：电脑在 PLC 登记后直接 FTP 到已绑定的控制柜工程，PLC 再 RETR 回读核对。填写控制柜 FTP 地址、账号和密码；旧 PLC 会在建立 FTP 前拒绝。

两种方式都不会跳过 PLC 上传许可、固定入口、版本标记和整组确认；都不会自动登记、加载、确认加载、使能或运行。回执记录 `transport` 和各阶段耗时，可用同一份约40KB作业比较。

## 第一次验证与日常使用

先按现有R6.3方式微调并捕捉实验起点，退出微调、停止并断使能。之后可保持PLC连接。

1. 打开“导入G代码”。可一次选择一个或多个文件；下方按执行顺序列出 `auto_01、auto_02…`。每个文件的坐标都以同一个已保存起点为零点；不会把后一文件自动平移到前一文件终点。
2. 默认勾选“导入并转换通过后自动上传”。如要先检查清单，取消勾选，再点击“保存并经PLC上传”。转换、保存和上传都不自动加载、使能或运行。
3. 全部文件上传、回读及PLC整组确认通过后，窗口显示“可用作业号11”，主界面编号框填入11。关闭窗口后，左侧显示本次自动作业补丁，选择各 `auto_XX` 可查看对应源程序和轨迹；这是本地生成文件，不是柜内实时目录。转换后尚未上传或上传失败时会显示对应状态。作业目录保留原始G代码、转换映射、补丁哈希和回执。
4. 关闭上传窗口，按 **登记 → 加载11号 → 确认加载 → 使能 → 运行** 操作。已登记的会话可沿用；每次上传都会撤销旧加载确认，仍要重新加载和确认本次版本。
5. 首次先只用 `examples/01_x_1mm.nc`，再导入其他短轨迹，确认控制柜确实使用新内容且无需重新绑定11号。检查柜内 `_project.srd` 起点数值、10号手动功能及返回起点仍有效。
6. 再选择两个示例，验证多个轨迹按清单执行。当前转换只生成**空跑运动**，没有接焊机起弧和送丝输出；保留原转换器支持范围和速度设置。

## 上传后如何防止跑旧内容

每次导入生成三个1～32767的版本标记。PLC在完整上传后发布本次标记；只在选中11号、手动服务未占用参数时，复用现有AI5～7通道传入。入口及每个轨迹的SRP写入标记常量，SRD也保存标记；程序先核对两者与PLC一致，再进入本段运动。

若SRP、SRD或子程序仍是旧缓存，会提示 `AUTO REVISION MISMATCH` 并退出，不执行该段旧轨迹。若后续子程序才发现旧缓存，前面已经完成的新轨迹不会倒回。本机制用于识别旧内容，**并不证明本柜固件的GDI加载一定刷新全部缓存**。遇到提示需停止并保留回执，核对柜内重载方式；不要把FTP回读成功当成解释器已更新。

PLC重启、目标配置变化、部分更新或上传失败后，11号不会被当作本次可用作业。恢复后完整重传；旧的多余 `auto_XX` 文件保留但不会被新入口调用。10号捕捉与回程保持独立。
