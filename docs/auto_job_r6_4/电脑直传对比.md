# 两种传输方式

R6.4 现在提供两个上传选项，后面的作业流程相同：**登记 → 加载 → 确认加载 → 使能 → 运行**。两种方式都只更新 `auto_main` 和 `auto_01`～`auto_15`，保留10号手动服务、实验起点和回程文件；都不自动加载或运行机器人。

## PLC 转传（批量提速版）

电脑把文件块写入 PLC，PLC 用 FTP 传入控制柜，再用 RETR 回读并校验。FTP 数据块上限改为8192字节，实际发送/接收多少就推进多少，保留最后短包、EOF、CRC和清理联锁。Modbus 文件协议仍是固定120字寄存器、每帧192字节，避免破坏现有协议。

## 电脑直传（SDK 手册 FTP 方案）

电脑先向 PLC 登记本次固定作业并取得上传联锁，然后按 STEP SDK 手册的 FTP 流程直接连接控制柜：`USER/PASS → CWD → TYPE I → PASV → STOR`。PLC 不接收文件内容，只通过 FTP `RETR` 回读控制柜中的每个文件，核对长度和 CRC；全部文件通过后才放行11号。SDK 的私有 `sendFile/recvFile` 没有作为外部接口调用，因此此选项使用同一套 FTP 协议，便于现场比较。

直传只允许 R6.4 文件桥（协议版本 `0104`、能力位8）和已绑定的固定自动作业。旧 PLC 会在建立 FTP 前拒绝，不能误写旧工程。FTP 用户名和密码只在本次运行内存中使用，不写入回执。

## 怎么比较

先用同一份约40KB、包含空 SRD 的作业，各跑一次，保存上传窗口中的回执。回执包含：`transport`、`total_ms`、`direct_ftp_upload_ms`、`transfer_to_plc_ms`、`plc_ftp_verify_ms`。比较时以“回读通过、作业号11放行”为前提，再看总耗时。PLC 转传更适合现场网络只允许电脑访问 PLC 的情况；直传更适合电脑能直接访问控制柜 FTP 且希望跳过 Modbus 搬运的情况。

## 现场启用

1. 先按 [从这里开始.md](从这里开始.md) 完成一次性11号绑定和 R6.4 PLC 文件桥编译。
2. 打开“导入 G 代码”，在传输方式下拉框选择“PLC 转传（批量提速版）”或“电脑直传（SDK手册FTP方案）＋ PLC回读校验”。
3. 选择直传时填写控制柜私有 IPv4、FTP 端口、用户名和密码；PLC 地址仍填写电脑侧 PLC 地址。
4. 先用短作业验证，再做40KB和多文件比较。任一阶段校验失败时，窗口只报告失败并保留回执，不自动重试或加载机器人。
