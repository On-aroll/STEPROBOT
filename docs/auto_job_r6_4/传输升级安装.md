# 已有 R6.4 的传输升级

本次只更改文件通道，提供 **PLC批量转传** 和 **电脑直传（SDK手册FTP方案）＋PLC回读校验**。如果现场还未装 R6.4，先按 [从这里开始.md](从这里开始.md) 完成自动入口基础配置。旧三程序固定覆盖包继续停用。

**2026-11-18 收尾修复：** `FB_FileSocketIo` 已补充 `ERR_SOCK_CLOSED` 的正常关闭处理；已安装早期提速代码且出现回读收尾 F223/220 时，只更新该功能块实现区，见 [FTP回读收尾修复.md](FTP回读收尾修复.md)。

1. 把现场正在使用的 PLC 工程另存副本；保留原 FTP 地址、账号、许可、映射和实验起点。包内 `rollback/` 保存的是本次修改前的R6.4文件通道源码，现场回退优先使用自己的工程副本。
2. 在库管理器核对 `CmpHCTCPIP 1.0.0.7`，添加/解析 `SysSocket 3.5.9.0`、`CmpErrors 3.3.1.40`。本版批量后端使用1.0.0.7里的隐藏符号 `GetSocketInfo`、`SOCKET_INFO`；必须由现场编译确认可访问。
3. 新建函数 **F_FileCrc32Fast / UDINT**，复制 `plc/F_FileCrc32Fast/declaration.txt` 与 `implementation.txt`。
4. 新建功能块 **FB_FileSocketIo**，复制其同名目录声明与实现。
5. 完整替换现有 **FB_FileFtp** 的声明区和实现区，再完整替换 **PRG_FileBridge** 的声明区和实现区。不要只追加几行；也不要把被调用的函数/FB名自动声明为 INT。
6. 原 R6.4 的 `PRG_RobotBridge`、R6.3手动桥、保持起点区、10号手动程序和11号固定绑定沿用。循环仍为 RobotBridge → ManualBridge → FileBridge，再发参数。新增函数和FB不单独加任务。
7. 在 InoProShop 编译得到0错误后，由现场操作者执行下载。先观察任务执行时间和看门狗余量，使用短文件验证，再传同一份40KB作业比较。若隐藏符号不可用、库版本不符或其他编译错误，保留原工程并提供错误文本；不要删除联锁或回读来消除错误。
8. 用本包启动器打开新的候选上位机，在导入页面选择传输方式。直传需电脑能访问控制柜FTP，且地址对应PLC回读的同一控制柜；PLC侧仍使用原有FTP账号配置。

新PLC文件桥状态：HR6247能力13、HR6248版本0x0104、HR6261批量8192、HR6262后端1。电脑直传在旧PLC上会提前拒绝。

成功后窗口显示总秒数，回执记录每个文件的搬运/直传和PLC回读耗时。比较方法见 [电脑直传对比.md](电脑直传对比.md)。后续仍由你点击登记、加载、确认加载、使能、运行。
