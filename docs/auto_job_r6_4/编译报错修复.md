# F_FixedFileValid 调用报错

2026-11-18现场构建报5错误：`FB_FileFtp` 实现区196/199行出现C0231、C0077、C0035，声明区130行提示C0181重名。

已核对已保存工程，并由用户贴出的声明区确认：`FB_FileFtp` 最后一个 `VAR` 区域多了这条局部变量：

```iecst
F_FixedFileValid: INT;
```

这条INT变量与独立的BOOL函数同名，使 `F_FixedFileValid(sFileRun)` 被识别为调用局部变量，后续BOOL判断也随之报错。

只删除这条局部变量声明，保留 `END_VAR`、实现区的函数调用，以及工程树中的 `F_FixedFileValid (FUN)` 对象。声明区末尾应为：

```iecst
    xPasvValid : BOOL := FALSE;
    xPasvInTuple : BOOL := FALSE;
    xPasvClosed : BOOL := FALSE;
    xPasvHasDigit : BOOL := FALSE;
END_VAR
```

随后重新编译。不要把局部变量改成BOOL，也不要删去文件名校验条件。独立函数的声明应为：

```iecst
FUNCTION F_FixedFileValid : BOOL
VAR_INPUT
    sName : STRING(64);
END_VAR
```

其实现区保持：

```iecst
F_FixedFileValid := F_AutoFileIndex(sName) > UINT#0;
```

交付源码及分区片段中没有这条INT变量。安装说明已改为先创建函数，再替换桥接程序；若IDE弹出自动声明提示，不要把函数名创建为局部变量。本次修复的现场编译结果待重新构建确认。
