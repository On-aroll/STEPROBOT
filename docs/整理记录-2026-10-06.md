**校验（全部通过）**

- 分页符 `U+000C` 数量与 PDF 页数逐一吻合：错误详细描述 386/386、SPad V1.8.1.20241015 283/283、用户编程手册-1.8.1.20241015 154/154、1STEPStudio 148/148。

**一处必须说明的差异：重转的字节数比 `INDEX.md` 原记载小 1~5 KB。**

原索引 KB 口径经核对为 `floor(字节/1024)`——用存活的 26 份逐份验证过（动力学 46,011 B → 44.9 → 记 45；线激光 56,271 B → 54.9 → 记 54，取的是截断）。按同一口径，重转的 10 份都比原记载小 1~5 KB（例：错误详细描述原记 323 KB、现 318 KB；PLC 原记 96 KB、现 91 KB）。原因：**原转换不是 pdftotext**——`INDEX.md` 自己的"转换质量自检"提到动力学那份曾转出 27 行非法 UTF-8（数学斜体符号被写成 CESU-8 代理对），而 pdftotext 不会产出这种编码。两套管线输出存在细微差异，故旧 KB 数对这 10 份不再适用，`INDEX.md` 已按实测值更新并在表中标 †。

## 4. 可复现的核对命令

```bash
# 36 份 PDF 是否都有对应文本
comm -23 <(ls "STEPStudio 4.7.0/bin/help documentation/"/*.pdf | sed 's|.*/||; s|\.pdf$||' | sort) \
         <(ls _extract/studio_txt/*.txt | sed 's|.*/||; s|\.txt$||' | sort)

# 模型文件是否在位、哈希是否与记录一致
sha256sum "STEPStudio 4.7.0/STEPLibrary/Robots/SR175-3200.srlib"

# 工作站是否与备份逐文件一致
diff <(cd "STEPROBOT-Recovery/before-restore-20260928/STEPStudio 4.7.0/Project" && find . -type f -exec sha256sum {} \; | sort) \
     <(cd "STEPStudio 4.7.0/Project" && find . -type f -exec sha256sum {} \; | sort)

# 两层 Studio 是否只差 unins000.dat
diff <(cd "STEPStudio 4.7.0" && find . -type f ! -path './STEPStudio 4.7.0/*' -printf '%s\t%P\n' | sort) \
     <(cd "STEPStudio 4.7.0/STEPStudio 4.7.0" && find . -type f -printf '%s\t%P\n' | sort)
```

> 注：本机 bash 不支持进程替换，以上命令需先落盘到临时文件再 `diff`。
