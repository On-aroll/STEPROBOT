## 3. 在 STEP Studio 中逐项打勾

本阶段使用 **PC 虚拟控制器**，操作对象为离线工作站。

- [ ] **启动与授权**：打开 `STEPStudio 4.7.0\bin\STEPStudio 4.7.0.exe`，进入主界面，记录软件版本及授权/试用状态。
- [ ] **准确机型**：基础 → 机器人库，搜索 `SR175`。在“本地机器人”或“在线机器人”中选择 **SR175-3200 / SR175/3200**，不要选成 2700 臂展的条目。
- [ ] **完整模型**：在线页下载后显示“模型及系统文件已就绪·可离线导入”，导入到场景。若使用了其它库位置，记录界面右下角“模型库位置”的实际路径。在线是否有该机型，本次没有验证。
- [ ] **机器人系统**：按手册 2.2.4 / 3.1 新建一个独立工作站和机器人系统，记录保存路径。导入三维外观模型之后，还需创建机器人系统才能继续。
- [ ] **虚拟控制器**：在“控制器”栏打开控制器，等右下角显示“运行中”，再打开 HMI 并登录。记录失败时的完整报警，不只记录“打不开”。
- [ ] **坐标与工具**：确认世界/机器人基座/工件/工具坐标系，记录 TCP 的位置、方向和单位。打印头尺寸未确定时可用临时工具，但需明确标为示例参数。
- [ ] **手动操作**：在虚拟 HMI 内改变一个关节，观察模型动作与关节读数；再改变 TCP 位置，观察不同操作方式的差别。
- [ ] **最小程序**：在可达区域教 3～5 个点，以 PTP 接近，用 Lin 走一条直线或小矩形，退出打印区域；保存程序并运行一遍。
- [ ] **打印路径演示**：在不启用真实打印设备的离线场景中，把单层路径复制为少量层，记录假定层高、道间距、速度、工具姿态和各层连接方式。此时验证的是路径组织，不是沉积效果。
- [ ] **可重复运行**：保存并关闭工作站，重新打开后仍能运行；保留工作站、程序、参数表和一次录屏。

## 4. 若需要自己的算法驱动仿真

这是下一层验收，不是“装好 Studio”自然附带的能力。

启动对应虚拟控制器后，可先在本机检查监听：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 30312 -ErrorAction SilentlyContinue
Test-NetConnection 127.0.0.1 -Port 30312
```

解释结果要分层：

1. 没启动虚拟控制器时端口不通，没有判断接口支持性的意义。初次检查没有监听，后续已启动并通过 SDK 采集，见联调验收记录。
2. 端口通只表示 TCP 可连接；还需核对监听进程、SDK 初始化、状态读取及与虚拟 HMI 的一致性。
3. 在确认进程属于虚拟控制器后，先用**只读**接口验证，不从运动命令开始。当前 C++ 探针 IP 写在源码中，默认是真机地址 `192.168.39.220`，不会自动切到本机。
4. 如果本机不通，核对虚拟控制器启动、绑定地址、设置及厂商支持情况；不能只凭这一次失败就断言没有接口。

现有手册未提供足以确认 Studio SDK 接入的说明。**“没搜到 API”不等于“绝对无法驱动”；“端口通”也不等于“SDK 零改动即可用”。**需要测到哪一层，就把结论写到哪一层。

如果最终需要自建模型，再准备 SR175/3200 的连杆参数、轴零位与方向、耦合关系、限位、TCP 和基座/工件坐标关系。用多组相同关节角，对照独立参考位姿检验模型，分别记录位置与姿态误差及参数来源。模型自己的正解和逆解互相算回去，并不足以证明它与真实机器人一致。

## 6. 面向论文：第一阶段需要留下什么

运动仿真能帮助检验路径是否可达、姿态如何变化、是否触及关节限制，以及已配置碰撞对象之间的干涉情况。仿真显示无碰撞，其意义也只覆盖模型和检测配置的范围。

**熔池、温度场、层高成形、残余应力和变形是否可信，需要对应过程模型、材料/工艺参数和验证数据。机械臂画出多层轨迹，不能替代这些结果。**本次没有建立或验证这些过程模型。

先为每次实验保存一张记录表：

| 记录项 | 内容 |
|---|---|
| 问题 | 这次只想检验哪个问题，例如同一几何路径上姿态选择对可达性的影响 |
| 输入与来源 | 准确机型、工具、坐标系、路径、关节初值、速度、圆滑、软件版本；标清示例值与实测值 |
| 对照 | 固定相同条件，用现有路径作为基线，先改变一个因素 |
| 输出 | 完成情况、不可达点、关节范围、程序用时；有可靠数据接口后再计算轨迹误差等指标 |
| 证据与边界 | 工作站、程序、日志/录屏、代码版本、结果图；标明哪些只是示意，哪些经过校验 |

你可以用这五个问题检验自己是否摆脱“只能照着点”：

1. 为什么同一个 XYZ 数值，在换工具或参考坐标系后可能对应不同动作？
2. 为什么 PTP 和 Lin 终点相同，中途路径仍可能不同？
3. 改速度和改圆滑分别影响什么？我能先预测，再操作验证吗？
4. 程序不运行时，我能区分模型未就绪、虚拟控制器未运行、程序状态问题和不可达目标吗？
5. 这张仿真图到底验证了什么，哪些真实打印现象没有被模型覆盖？
