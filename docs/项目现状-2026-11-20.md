# 项目现状与文件索引 · 2026-11-20

本文件是 R6.4 的技术事实、交付物和验证范围索引，供后续整理材料使用。正式工作总结尚未编写。旧文档中的“候选”“尚未连接现场”和旧界面截图对应各自发布日期；当前状态以本索引及本次验证记录为准。

## 系统与流程

设备：STEP SR175-3200 六轴机器人、汇川 AC802 PLC、Windows Qt 6.8.2 上位机；焊机现场机型为 WSME-400-PLUS，经 ATR-EtherCAT 通信盒接入。

```mermaid
flowchart LR
    G[G 代码与当前显示快照] --> C[转换 SRP/SRD 与版本标识]
    C --> P[Modbus 批量传 PLC]
    P --> F[PLC FTP 上传控制柜]
    C --> D[电脑 FTP 直传控制柜]
    F --> V[PLC 回读与版本确认]
    D --> V
    V --> N[可用 11 号作业]
    N --> R[登记 / 加载 / 确认 / 使能 / 运行]
```

“SDK 直传”在本项目中采用 SDK 手册给出的 FTP 文件传输协议，实际文件通道由上位机 FTP 客户端实现，不调用 SDK 运动接口。文件不经 PLC 转发，上传许可、回读和可运行版本仍由 PLC 文件桥管理；两条路线共用后续运行流程。

## 当前实现

| 部分 | 当前行为与边界 |
|---|---|
| 固定程序号 | 10 号为 `pcjob_manual_r63.sr / manual_service`；11 号为同工程的 `auto_main`。自动入口按导入顺序调用 1～15 个 `auto_XX`，无固定三程序限制。现场需先正确完成一次绑定。 |
| 日常更新 | 只更新 `auto_main.srp/.srd` 与本次 `auto_XX.srp/.srd`，不覆盖 `_project.srd`、手动服务及实验起点。上传成功后须重新加载并确认版本。 |
| 微调与起点 | 保留手动调整、捕捉实验起点和返回起点。自动运行先检查已捕捉起点。姿态使用捕捉起点的固定末端方向；不把 J5/J6 锁死为零。竖直向下的实际姿态需按工具/坐标系在现场确认。 |
| 文件传输 | PLC FTP 发送/回读块增至 8 KiB，并正确处理部分发送、WouldBlock、分片尾部与连接关闭；保留逐字节或 CRC/长度校验。电脑直传可独立选择，无需先连接顶部 SDK 控制会话。 |
| 原文与上传一致 | 默认上传当前显示的 G 代码字节快照及其转换参数。更换文件后，原文、工程树、轨迹同步刷新；失败清除旧轨迹。多文件作业保留各文件来源及行映射。 |
| 连续上传 | 成功终态可直接开始下一次；FTP 失败后在本次所有权与应答确定时 ABORT、关闭并 RELEASE。对稳定的超时关闭终态进行核对后释放。未知关闭、PLC 重启、所有者变化或命令未确认时停止，不自动重传文件。 |
| 密码输入 | 现场安装版预填固定密码，支持小眼睛显示/隐藏。公开源码从本机配置或环境变量读取，配置仍可达到同样的免重复输入效果。 |
| 姿态与轨迹 | 连接 PLC 后可独立读取六轴反馈，运行期间继续更新；失效反馈保留最后姿态并标记过期。第一页与其余页面支持规划轨迹高亮、轨迹细节和机器人全景。规划轨迹不等于实测 TCP 轨迹。 |
| 操作界面 | 起点操作排在自动运行前，手动页包含登记等操作；增加焊机页和联动打印页，整合机器人操作、姿态与焊接参数，适配普通、小窗口及宽屏。 |
| 模式切换 | 提供独立 SDK 模式组件及手动/自动/外部自动切换界面，需停稳、断使能和回读确认；现场完整验收仍待完成。 |
| 焊机 | 复用旧工程的 32 字节 PDO 编解码和会话联锁，并增加新机型只读诊断。现场实际 PDO 为每向 16 字节，尚未取得匹配协议；旧参数/状态解析不能作为新机型验收依据，起弧与机器人运动的实机同步尚未完成。 |

## 验证事实

- 现场回执已有 PLC 转传及电脑直传的 `COMPLETE`，两者均有上传后 PLC 回读记录；其中一笔 PLC 转传回执总耗时约 4.703 秒。该数值仅对应该次作业及现场环境，不代表所有文件的吞吐量。
- 40,000 字节 FTP 上传加回读在离线 ST 扫描模拟中约 54 扫描完成，是扫描数基准，不能直接换算为实机耗时。早期 40 KB/10 分钟问题对应旧的逐扫描小块处理。
- 2026-11-20 直传 FTP 登录失败 530 后，旧上位机遗留文件会话，随后 PLC 租约超时到 900；后来上传曾依赖人工 `xReset`。本次已修正上位机清理与终态释放，并通过模拟控制柜、模拟 PLC 和实际 ST 源码解释执行检查；该恢复修复尚无新的现场复测回执。
- 当前仓库源码的重新构建、CTest、ST 与模式组件验证结果见[本次验证](verification/2026-11-20/README.md)。离线验证不替代 InoProShop 编译、设备运动、工具标定和焊接工艺验收。
- 仓库复验修正了焊机请求超时当次仍可能续租的判定顺序；未替换现场运行程序。一次小窗口轨迹截图在Qt6Gui中异常退出，随后单项复验通过，根因仍待复现；原始失败记录保留在验证目录。
- 新点阵示例 `dianzhen_R64_dryrun_36cm.nc` 使用 G 代码毫米单位表达 360 mm 范围，162 根杆件、379 段运动；段间经抬高的空移路径移动，不在每个单元间回到固定 Z=50 mm。它是空跑路径，不包含机器人碰撞或可达性证明。旧 36 mm 文件保留用于回归测试。
