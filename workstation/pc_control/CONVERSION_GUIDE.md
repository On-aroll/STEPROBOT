# G 代码 → STEP 程序工程 → STEPStudio → 上位机

## 输入需要先明确什么

工艺需求首先要落实为路径坐标、顺序、进给、等待、工具姿态与工艺输出。轮廓或模型可由已有 CAM/切片流程产生 G 代码；简单实验也可以直接填写路径。当前转换器处理固定姿态的三轴运动，输出空跑工程；不会根据一句自然语言自动确定工件零点、工具、成形参数或安全空间。

G90 的绝对坐标是**相对已记录工件零点**，不是控制柜 WORLD 的数值；工件零点取 `capture_home` 记录的 TCP，轴向平行 WORLD。工具固定 `Default`，姿态继承起点。安装真实打印头后必须先明确实际 TCP 与坐标变换，不能直接把此默认约定当作工具标定。

## 使用转换窗口

1. 打开工作台顶部「G 代码转 STEP 工程」。选择 UTF-8 G 代码，或在左侧填写。
2. 填写 G0 的受限直线速度（mm/s）和圆弧弦高误差（mm）。F 仍是 G 代码的 mm/min。
3. 点击「检查 / 转换」。有不支持的指令、圆弧半径不一致或范围越界时，报告会指出源行，禁止生成工程。
4. 如源文件包含 M3/M4/M5/M11，只有明确勾选忽略工艺输出才可转换。这样得到的程序仍不出光、不送粉、不挤出。
5. 点击「生成 STEP 工程 ZIP」。同时输出原始 G 代码、行映射和转换报告。状态保持「待 STEPStudio 验证」。
6. 「打开 STEPStudio」和「打开导出目录」便于进入下一步。转换不会自动导入、启动控制器或传输到实机。

支持 G21、G17、G90/G91、G94、G91.1、G0/G1、带相对 I/J 圆心的 G2/G3 局部圆弧、整圆和螺旋、模态 F、G4 P 秒、兼容 G4 T 秒、N 行号、M2/M30 和注释。圆弧采用直线离散，最大角步长 5°，默认弦高误差 0.05 mm。输入最多 32 KiB、1000 个路径点，XYZ 相对偏移各限 ±1000 mm；F 为 0.06–1500 mm/min。G0 也按受限直线执行，默认 5 mm/s。

弦高误差描述离散几何，不等于实际 TCP 误差；控制器的圆滑过渡、加减速和工具模型还会影响实际路径，需要在 STEPStudio 和后续实测中检查。

G20、G18/G19、R 圆弧、绝对圆心 G90.1、刀补、工件偏置、宏、挤出轴和未明确忽略的工艺代码会被拒绝。这是明确的受支持子集，不是完整 CNC 控制器。距离模式、I/J 与等待语义参照 [LinuxCNC G-code 文档](https://linuxcnc.org/docs/html/gcode/g-code.html)，原生语句采用工作区厂家编程手册和已核对工程。

## 生成的工程包含什么

```text
GcodePreview.sr/
  _project.srd       公共 pHome、pHomeCart、homeSaved
  capture_home.srp   前置：记录当前六轴和 TCP，不发运动
  capture_home.srd   前置程序变量，可为空
  gcode_path.srp     主程序：转换后的运动、等待与完成标记
  gcode_path.srd     主程序变量：路径点、速度和状态
```

G 代码转换包不生成项目专属 `go_home`。`capture_home` 是 G 代码作业自身的工件坐标基准；它与上位机设备级返回起点是两项不同的状态。导入的旧工程即使含有 `go_home`，工作台也不依赖或调用它。

ZIP 是**机器人程序工程**，不等于含机器人、工件和场景的 STEPStudio 完整工作站。ZIP 旁的 `mapping.json` 绑定 G 代码原文、原生文件哈希和 SRP 行范围；`source.gcode` 保留源文件；`conversion.txt` 记录坐标约定、参数和检查事项。

## STEPStudio 验证

在现有 SR175-3200 工作站中导入程序工程，或将解压后的 `.sr` 目录放入工作站的 `SRSystemFile/UserPrograms`，再从该工作站虚拟示教器的工程/程序管理选择。先确认工具、工件、原点、姿态和场景。不要把程序 ZIP 当成 `.srstn`/`.srpnt` 工作站文件直接打开。

在确认过的初始姿态运行 `capture_home`，再加载 `gcode_path` 仿真。检查可达性、限位、连续运动、碰撞、速度、终点和工艺顺序。这个程序只定义该 G 代码作业的坐标基准，不是上位机返回目标。输出无激光或送料控制，空跑正确不能证明实际成形正确。

仿真通过后，保留同版本 ZIP 与映射再导入上位机。ZIP 仅重新压缩、且所有 SRP/SRD 原始字节哈希一致时，可继续使用原映射；如 STEPStudio 修改了程序或变量，旧映射失效，必须重新转换或重新核对映射。软件没有把「成功生成 ZIP」标记为「已完成场景验证」。

## 上位机完整工程与编辑

工程树按程序分组，并显示每个 `.srp`、同名 `.srd` 与 `_project.srd`。`capture_home` 标为 G 代码作业坐标基准；旧工程中的 `go_home` 标为旧工程文件，上位机不调用。选中程序或文件查看原文，点击「编辑文件」修改本地副本。G 代码生成的 SRP/SRD 也可以进入编辑器。

保存到工作副本不等于写入控制柜。任一原生文件修改会清除旧映射、旧校验状态和旧预览，随后可另存完整 ZIP，送回 STEPStudio 验证。换工程或关闭时，未另存的修改会提示保存。编辑器不替代厂家编译器；语法和动作还需在 STEPStudio 检查。本版本转换器生成且文件完全一致的工程可继续上位机本机仿真，一般原生 ZIP 可查阅和编辑；G 代码可通过「直发转换程序」执行 SDK 临时运动流；原生工程文件仍按 STEPStudio/U 盘流程传输，柜内其他程序须核对内容、入口和速度。

## 上位机设置和返回起点

「将当前位置设为起点」保存到上位机配置 `workstation_origins.json`，记录六轴、WORLD TCP、工具、控制器身份和时间。记录动作不发运动命令，也不写入当前工程。切换工程或重新连接到同一设备后仍可使用；不同实机 IP、序列号或机型分开保存。实机连接同样可记录其当前位置。

「返回起点」在仿真与实机界面均开放，自动模式会先切手动执行、停稳后切回。当前运行验证以本机厂家虚拟控制器为准。输入末端速度上限（mm/s，默认 25，最高 250，受当前手动笛卡尔限速进一步约束）后，上位机按当前六轴和记录目标生成最多 24 段关节 PTP，并为各段计算 WORLD TCP。以当前 SR175-3200 连杆及工具长度计算保守速度界，向下换算关节倍率并保留 10% 余量，实际速度可能更低；分辨率不足时拒绝移动。界面先显示六轴路径、TCP 位姿、末端限速和预计时间；确认后控制端检查计划编号和有效期、起始关节、工具尺寸、模式、使能、报警及关节限位，再调用厂家 `JogToRobotAxisposCmd(ePTP, ...)` 逐段移动。运行中持续监视轴速、实际 TCP 速度、倍率、连接和停止状态，TCP 超过输入上限即停止；最多运行 300 秒。点「停止发送」可打断回程，只有到位或静止停止得到控制器回读确认后才报告结果。内部规划命令为 `planhome_tcp`，避免旧版关节速度参数与新版 mm/s 混用。

预览通过厂家 `TransSDKGetKinematics` 对关节路点计算 TCP 位姿。它不检查工作站几何碰撞；当前没有加载工件、夹具和围栏模型，因此不能据此声称自动避障。关节 PTP 的 TCP 轨迹可能弯曲，操作员仍需确认整段净空。起点返回不加载、修改或依赖 `go_home`，也不改变当前工程。实机界面会发出运动指令，现场必须核对控制柜配置与限速参数并确认净空；软限和普通停止不代替实体急停。

## C++ 命令行转换器

`native/StepGcodeConverter.exe` 与窗口共用同一 C++ 转换实现，不依赖 Python。

```powershell
.\native\StepGcodeConverter.exe --input 'D:\path\input.gcode' --output 'D:\path\program.zip'
```

可选 `--rapid-mm-s 5`、`--arc-tolerance-mm 0.05`、`--omit-process-outputs` 和 `--template <已核对v4 ZIP>`。输出路径所在目录应已存在。转换失败返回非零状态码，不写入可执行 ZIP。
