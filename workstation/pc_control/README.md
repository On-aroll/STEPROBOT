# STEP 打印作业台

在 Windows 资源管理器双击 `Open_Pendant.cmd`。入口运行 `native/StepWorkstation.exe`，使用 C++20、Qt Widgets 和 MSVC x64。工作台通过本地进程管道调用同目录的 `helix_pc.exe`，继续使用已验证的 STEP C++ SDK 控制端和厂家虚拟控制器。启动无需 Python。

顶部「打开工程 / G 代码」导入 ZIP 或 G 代码。「G 代码转 STEP 工程」提供独立转换窗口，生成完整程序包、原文、行映射和报告，随后在 STEPStudio 验证。「工程 / 工具」按工程文件、G 代码联动、示例和记录分组，并提供界面说明。「实机 STEP SDK」通过 TCP 连接控制柜，地址可写成 `IPv4:30312`；经控制器许可后可请求手动/自动切换、伺服使能、点动、返回起点、加载柜内程序以及启动/停止，各操作均以实际回读确认。红色「急停」按钮直发 STOP+MSTOP 并中断点动/回程循环。`Modbus TCP` 尚无经核对的寄存器映射，连接入口禁用。

中间轨迹窗口显示计划路径。「STEP 虚拟控制器」会复制独立工作站，启动 STEPStudio 自带的 `1-NonReal.exe` 和运动进程，再加载并运行原生程序。STEPStudio 的工作站、工具、碰撞和场景验证可通过导出的 ZIP 继续完成。

左侧为完整工程树：主程序、前置程序、各程序 SRD 和公共变量都保留。旧工程里的 `go_home` 作为原文显示和编辑，上位机回程不调用它。选择文件查看，点「编辑文件」修改本地工作副本，点「另存工程 ZIP」保存。修改任一文件会清除旧的校验状态和 G 代码映射，不会写入控制柜；关闭或换工程前会提示保存。变量文件不按执行行高亮。带有效映射的工程树另有 G 代码节点。中间采用浅色网格，支持等轴、XZ、XY 视图，并用回读同步当前行、路径颜色和 TCP 标记。

连接、运行和记录状态统一采用灰色待命、蓝色进行中、红色需处理。当前下一步操作会用蓝色主按钮突出显示，按钮尺寸保持一致。连接空的虚拟控制器后可直接打开文件，工作台会准备该作业，之后由用户确认开始。

## 手动点动与记录

1. 不导入工程也可以选择「STEP 虚拟控制器」并点顶部「连接」。回读为手动且已使能后，在「手动点动」选择坐标系。已有自动作业时，先停程序，再切到手动。
2. 坐标选项包括关节、世界、基座、工具和用户/工件。用户坐标使用柜内已定义的 CARTREF 名称，隔离仿真模板中有 `SimPart`。无论选择哪个坐标系，底部都实时显示 A1–A6 角度，单位为 °。工具坐标页的 XYZ/ABC 用来指示点动方向。
3. 直接填写 XYZ 平移速度，单位 mm/s，上限 250 mm/s。关节和姿态速度另填，单位 °/s。速度换算使用配置工作站的手动参数，向下取控制器可用倍率精度；实机使用前须核对这些参数与柜内导出配置一致，不能把本地参数当成已经核实的实机限速。末端实际速度另由控制器回读。按住「−」或「+」期间持续点动，松开按钮发送停止（另有 10 秒保护上限），以停止反馈为准。
4. 右侧「记录」区的「另存遥测 CSV」可单独保存点动回读，结束另存或断开会话后关闭文件。数据包含电脑时间、控制模式、程序状态、六轴角度、世界位姿、末端速度、应用的手动速度及其单位。点动过程中也回传中间样本，操作结束后仍检查停止反馈。

「切到手动／自动」只请求切换模式，保留已加载程序，不改倍率、不自动使能。点动仍要求回读为手动且已使能；「使能伺服」是独立请求，不启动程序。实机外部自动运行按现场流程选择 EXT；模式请求是否被接受取决于柜面/示教器模式选择、控制权限及安全条件，不能通过软件绕过。请求失败会显示 SDK 返回码、实际模式、使能状态和控制器消息号。示教器实体急停保持有效。

## 导入、卸载与加载柜内程序

1. 实机连接且停稳后导入有效新作业，上位机会请求卸载当前前台程序；运行、点动、回程或操作尚未确认时禁止换作业。卸载不删除柜内文件。
2. 点「加载当前程序」，按左侧 STEP 文件的工程名、程序名加载；也可在「柜内程序」填写名称后点「加载」。加载会先确认旧程序已卸载，再核对新工程名和程序名；不切模式、不使能、不启动。工程名带不带 `.sr` 均可，调用 SDK 时统一使用无后缀名称。
3. 名称匹配后，按现场条件选择运行模式并单独使能，最后点「开始」。已打开本地作业时，柜内为其他程序会禁止启动，不能把旧程序当成新作业运行。切手动不要求卸载已加载的自动程序。

ZIP 导入电脑与传入控制柜是两步。当前 SDK 公共接口只加载柜内已有文件，原生 ZIP 须先通过 STEPStudio 或 U 盘传入柜内，再点加载。同名不代表内容版本一致，仍需核对版本。G 代码使用「直发转换程序」边发送边执行，不使用柜内文件加载按钮。

### 设置与返回起点

在手动页移动到合适姿态，点击「将当前位置设为起点」。它只把当前六轴、WORLD TCP、工具、设备身份和保存时间写入上位机配置 `workstation_origins.json`，不改工程文件；按机型、控制器身份和实机 IP 隔离，重连和切换工程仍可读取。实机只读会话也能记录位置。

「返回起点」在手动和自动模式下均开放（自动模式时上位机先切到手动执行、完成并停稳后自动切回），仿真与实机均可使用。填写回程末端速度上限（mm/s，默认 25，输入范围 0.1–250，且不超过控制器手动笛卡尔限速），软件读取当前位置后生成最多 24 段的关节 PTP 路径，并调用 STEP SDK 正运动学计算 TCP 预览。根据当前 SR175-3200 配置中的连杆尺寸、工具长度和参与运动的关节限速，使用 `|v_TCP| ≤ Σ(radius × |omega|)` 保守换算并向下取整控制器倍率，保留 10% 速度余量及原有 10 °/s 内部关节上限；实际速度可能低于输入值。低于倍率分辨率时拒绝移动。弹窗展示每段六轴角度、TCP 位姿和末端速度上限；确认后重新核对工具尺寸、手动模式、使能及起始姿态，再执行。运行中监控实际 TCP 速度、六轴速度、倍率、报警、连接和停止状态，TCP 超过填写上限即停止，最长 300 秒。此为软件限制，仍需现场安全控制系统。

路径按关节空间分段，TCP 不保证走直线。当前工作站没有工件、夹具和围栏碰撞模型，预览不代表避障；移动前须由操作员核对全程净空。点「停止发送」可停止回程，结果必须等控制器确认停止后判定。

## 直接导入 G 代码

点「打开 G 代码」，选择 `luoxuan.txt` 或同一方言的 `.nc`、`.gcode`、`.ngc`、`.tap`、`.txt`。文件选择器默认打开 STEPStudio 的 `project` 目录。导入后可查看完整原文、路径、点数、圈数、终点偏移和累计等待时间。点「准备仿真」或本机仿真「连接」会加载原生 STEP 程序 `GcodePreview.sr/gcode_path`，随后单独确认启动。

- 断开会话后，双击运动行可选为仿真起始行。此前指令略过，增量坐标从新仿真的初始 TCP 计算。双击第一行恢复整单。剩余时间根据进给、倍率和停留时间估计。
- 未识别行标红并写入运行日志。原文保留，整份文件禁止执行，避免跳过会改变后续语义的指令。文件执行上限仍为 32 KiB。

- 以记录的 TCP 为工件零点，轴向平行 WORLD、固定 Default 工具和起点姿态。支持毫米、XY 平面，G90/G91、G0/G1、I/J 局部圆弧/整圆/螺旋 G2/G3、模态 F、G94、G91.1、N 行号、M2/M30。F 为 mm/min，范围 0.06–1500；G0 转为受限直线，默认 5 mm/s。圆弧最多每 5° 一段，并受弦高误差约束，默认 0.05 mm。总计最多 1000 点、各轴相对偏移 ±1000 mm。
- G4 P 为秒，兼容本项目 G4 T 秒。M10 保留为已忽略工艺输出。M3/M4/M5/M11 需要在转换窗口明确勾选忽略，才可生成空跑。未接入激光、送粉、挤出。G20、非 XY 平面、R 圆弧、刀补、工件偏置、宏程序等会报源行并阻止导出。详细流程见 [转换与工程编辑说明](CONVERSION_GUIDE.md)。
- `luoxuan.txt` 的路径包含四圈，终点相对原点为 `(0, 0, 332)` mm。仿真倍率 100% 时，`F24` 对应 0.4 mm/s，按路径长度、进给和等待估算约 33 分钟。既有 STEP 螺旋 v4 的速度和动作由其原生程序定义。

导入 G 代码时，后台后置转换器生成 `.srp` 动作和 `.srd` 点位变量，虚拟控制器执行生成的原生程序。界面保留 G 代码原文，通过源行映射跟随 SRP 行号更新。自动路径速度来自 G 代码的 F，单位 mm/min。

「G 代码转 STEP 工程」或「工程 / 工具 → 工程文件 → 另存完整 STEP 工程 ZIP」保存一层 `.sr` 目录，含主程序、用于工件坐标基准的 `capture_home` 和相关变量。设备级起点返回由上位机处理，转换工程不再生成项目专属 `go_home`。ZIP 旁保存 `.mapping.json`、`.source.gcode`、`.conversion.txt`。转换成功状态仍为「待 STEPStudio 验证」。导入 G 代码后也可使用「直发转换程序」执行 SDK 临时运动流，不需要先传输 SRP 文件。

G 代码先在本机隔离仿真验证。SDK 直发需要 Default 工具，确认后以控制端读取的当前位置为原点、WORLD 轴向执行，流中路径速度不超过 25 mm/s。它会启动临时 SDK 任务并分批发送运动语句，停止会取消尚未发送的操作并中断后续发送；它不是将完整工程保存进柜内。实机首次联调仍需核对控制柜、参数、初始姿态、净空和停止反馈。

## 导入 STEPStudio ZIP 与源行高亮

SRP 是机器人执行的原生指令，SRD 保存变量和点位。普通 STEP ZIP 不包含原始 G 代码；循环、变量、条件分支、关节运动和工具变换也无法通用地还原成原始 G 代码。导入 ZIP 后，左侧显示完整 SRP，不会用预览路径或时间估计生成虚假的 G 代码执行行。

- 「STEP / SRP 原文」按控制器的工程名、程序名和当前行号高亮，黄色箭头表示当前行，并自动滚动。循环回到较小的行号时也会跟随。绿色只标记已观测到且已经离开的行，未采样到的行或未执行的分支保留原样。程序不匹配、回读中断或行号越界时清除当前高亮。
- 本工作台导出的 `xxx.zip.mapping.json` 放在 ZIP 旁边，重新导入 ZIP 时校验所有原生文件和 G 代码原文，再恢复源行视图。同内容重新压缩允许继续关联；程序或变量字节改变时拒绝旧映射。对本版本生成且全部文件可精确重建的工程，同时恢复几何预览。可从工程树切回原生 SRP。
- 使用自己的转换工具时，让转换工具同时输出 G 代码与 SRP 行映射。「工程 / 工具 → G 代码联动 → 关联 G 代码及行映射」可选 `.mapping.json`，也可选 G 代码文件（旁边需有 `xxx.gcode.mapping.json`）。原文保存在映射文件中；另选 G 代码时还会校验其字节一致。仅有同名 G 代码不能可靠确定执行行。
- 映射格式沿用工作台导出的 schema 1：`project`、`program`、`zip_sha256`、所有 SRP/SRD 的 `program_sha256`、`source_sha256`、UTF-8 原文的 `source_bytes_base64`、`source_start_line`，以及 `source_map` 中的 `source_line`、`srp_first_line`、`srp_last_line` 和可选 `skipped_output`。SRP 行范围不能互相重叠；同一循环中的原生行无法唯一对应多条展开后的 G 代码时，需使用 SRP 原文查看。
- 「工程 / 工具 → 工程文件 → 导出当前文件原文」保存当前 SRP、SRD 或 G 代码。实验目录保留原始 `input.zip`、所选 `display.srp`/`display.gcode` 和源行映射信息。

上述校验确认本地 ZIP 与 G 代码映射的版本一致。实机柜内文件仍需现场核对，SDK 行号代表控制器回读的程序位置，不等于喷嘴已精确到达该行终点。上位机起点与返回不依赖工程内的 `capture_home` 或 `go_home` 程序。由本版本转换器生成、带有效映射且所有文件可精确重建的 ZIP 可继续本机仿真；其他新 ZIP 和修改后的副本仅供查阅、编辑和另存。转换版本核对不等于 STEPStudio 场景验证。

## 用现有螺旋工程试用

1. 点「打开工程 / G 代码」并选 `SR175_3200_Helix_Ready_25mms_v4.zip`，也可以从「工程 / 工具」载入螺旋示例。旧版工程里的 `go_home` 会作为原文显示和编辑，但上位机回程不调用它。
2. 选择「STEP 虚拟控制器」并点「连接」。面板在独立仿真站解压工程，记录仿真初始位并加载螺旋程序。看到仿真已连接后，检查自动模式和当前程序名。
3. 点「开始」并完成开始前确认，观察六轴、末端位置及速度回读。点运行控制区「停止发送」，等回读确认暂停或停止后可断开会话。
4. 暂停后点「重新准备仿真」，会从独立工作站的原初始姿态重新装载作业，随后需再次手动启动。上位机起点在手动页单独记录，不随工程变化；返回前会显示关节和 TCP 路径并要求确认。
5. 相机页的「打开本地图像」用于预览图片。实时相机采集尚未接入。

面板导入会校验本地 ZIP。ZIP 仿真运行开放给已核对 v4 及本版本可精确重建的 G 代码转换工程。原生工程文件仍使用 STEPStudio 文件传输或示教器 U 盘导入；面板可按工程名/程序名加载柜内已有程序。G 代码转换后的 SDK 临时运动流则直接由面板发送和执行。两种路径均可查看状态和停止。

## 自动实验记录

右侧统一的「记录」区包含试次备注、归档状态、另存遥测 CSV 和运行日志。每次从工作台发起运行，会在工作区 `outputs/workstation_runs/` 创建独立试次目录。「打开本次记录」打开最近一次试次，「工程 / 工具」可打开记录总目录。启动前必须能创建记录并写入初始样本。手动点动和起点返回可单独另存遥测。

| 文件 | 内容 |
| --- | --- |
| `input.gcode` 或 `input.zip` | 原始输入字节。仿真从中途行开始时仍保留原文件 |
| `program/` | 本地作业程序快照。实机柜内同名文件仍需现场核对 |
| `plan.csv` | 相对仿真起点的计划路径和可对应的源行 |
| `trace.csv` | 主机 UTC 时间与相对秒数、控制器行号、源行、位姿、六轴、速度、倍率、状态和可计算的路径距离 |
| `run.json`、`events.log` | 输入及程序 SHA-256、备注、起始行、结果、采样数、最大采样间隔、距离统计及启停与回读事件 |

仿真视图默认叠加蓝色虚线实测 TCP，可关闭。G 代码按当前源行对应的计划折线求最近距离，原生螺旋 v4 按整条计划折线求最近距离。RMS 和峰值反映已收到的样本，终点距离仅在控制器确认作业完成时填写。比较基于虚拟控制器回读，不能用来证明实机定位精度或材料成形质量。实机没有经过核对的坐标原点和同版轨迹时，只记录原始回读。

完成、停止、启动失败和回读中断分别归档。主机异常退出时，已写入的 CSV 和事件仍可读取，`run.json` 可能保留 `in_progress`，该试次结果需要核对。现场喷嘴干涉、连续插补、出料同步和安全联锁仍需要各自的验收。

「停止发送」使用普通 STOP。「急停」按钮直发 STOP（停程序）+ MSTOP（停运动），点动、回程和启动预检循环会因管道中出现急停指令而立即中断，并在停稳后回读确认。两者都是网络软件指令，不是断电级急停；现场断电级急停仍由示教器等实体安全回路执行。界面不会把普通暂停、停止或一般报警推断成急停。

- 作业启动检查期间可以点「停止发送」。排队中的 START、直发启动、柜内程序启动、点动和回程都会取消；START 发出前还会复查停止请求。停止或软件急停确认前拒绝新的操作。正在执行的厂家 SDK 调用返回后，控制端才能继续处理下一条命令。
- 停止确认需要控制器回读暂停或停止，并且 TCP 与六轴速度都低于停止判定阈值。超时或通信中断时，界面提示结果待确认。
- 本机仿真只有在本次程序回读过运行、结束且柜内 `simDone` 从 `FALSE` 变为 `TRUE` 时显示「作业完成」。普通停止、提前退出和实机程序结束分别按停止回读或结果待核对显示。
- 由本工作台启动的作业回读超时时，工作台通过仍存活的控制端尝试一次普通 STOP。通信链路失效时，柜内停止结果需要现场确认。当前没有激光输出或反馈接口，空跑保持锁定，解析错误时没有可执行作业。

## 控制端

Windows 命令行工具 `helix_pc.exe` 使用 STEP C++ SDK 连接控制柜。它识别 `SR175_3200_Helix.sr` 里的 `helix_25mms`。验证用的是工作区中的 `SR175_3200_Helix_Ready_25mms_v4.zip`，文件的 SHA-256 为 `e2c0746c66cb9045e71fabedc2c58b15add4dc6a929e7f38ce9378a611677c87`。现场不同的 ZIP 版本可能带有同名程序，请先通过工程导出或现场版本记录核对实际程序和参数。

电脑发出模式切换、点动、返回起点、卸载/加载、使能、启动或普通停止请求，SRC4L6 执行柜内程序。柜面模式选择及安全条件由现场操作员核对；上位机不能替代这些条件，所有请求均须核对回读。示教器实体急停始终保持有效。

接控制柜调试网口。在示教器「STEP → 控制面板 → IP」读出当前地址，让电脑的专用有线网卡与它同网段。SDK 单客户端独占，先退出其他 SDK 客户端，再在本目录打开 PowerShell。以 `192.168.39.220` 为例，实际值以现场为准。

```powershell
.\helix_pc.exe real 192.168.39.220
```

控制柜地址默认填入 `192.168.39.220:30312`，连接前可按示教器上的实际 IP 修改。选择「实机 STEP SDK」后点「连接」，端口固定为 `30312`。使用命令行时，显示 `access=start_stop` 后，在 `helix>` 输入 `status`。核对 `robot`、`cabinet`、`serial`、`project`、`program`、`mode`、`enabled` 和六轴角度是否和现场一致。连接状态和位置来自厂家 SDK，位置等循环数据没有控制器时间戳。核对结束断开会话，命令行用 `quit`。

## 现场监督下验证控制

实机端首次使用需现场监督。外部自动运行按现场流程选择 EXT；若手动模式请求未被接受，应先核对柜面/示教器模式选择和控制权限，不能认为外部自动档必然允许软件切手动。现场操作员确认工程版本、实际初始姿态和路径；已知螺旋通过现场流程记录 `pHome`，把机器人停在该点，加载 `helix_25mms` 到开头。首次电脑试验使用现场确认的低速倍率，并保持人员离开机器人工作半径；示教器实体急停随时可用。

```powershell
# 使用核实的实际 IP。
$ip = '192.168.39.220'
.\helix_pc.exe real $ip
```

控制入口接受 SDK 返回的 `SR175-3200` 或 `SR175/3200`，仿真另校验 `SRC2.7` 及本机虚拟控制器进程身份。型号匹配不代替现场柜型、固件和参数核对。显示 `access=start_stop` 后才开放控制命令，其他机型保留只读回显。断开或退出不能当作停机手段。

| 在 `helix>` 输入 | 作用和反馈 |
| --- | --- |
| `status` | 读取当前程序、模式、倍率、报警、关节和 WORLD 下的末端位置及速度。`state=0/1/2` 分别是运行/暂停/停止。 |
| `start` | 启动当前停止的柜内程序；已知螺旋程序额外核对 `homeSaved`、`pHome`、`dynPath`。其他程序须现场确认版本、入口和速度。`start_confirmed=running` 表示回读到运行。 |
| `stop` | 发普通 STOP，等待反馈为暂停或停止且末端速度接近零。它保留伺服使能时，机器人仍可能在新启动命令后运动。 |
| `estop` | 直发 STOP（停程序）+ MSTOP（停运动）软件急停，点动与回程循环随即中断，停稳后回读确认。网络软件指令，不是断电级急停。 |
| `manual` / `auto` | 只请求模式切换，保留加载程序，不自动使能或设置倍率；核对实际模式回读。 |
| `enable` | 单独请求伺服使能，核对使能回读；不启动程序。 |
| `unload` | 停稳后卸载当前前台程序，确认程序名为空；不删除柜内文件。 |
| `loadproj <工程> <程序>` | 停稳后卸载旧程序并加载柜内已有文件，确认工程名及程序名；不切模式、不使能、不启动。 |
| `runproj <工程> <程序>` | 加载柜内程序并直接启动，等价于 `loadproj` 后自动发 START。 |
| `sendrun "<指令流路径>"` | 执行工作台生成的 SDK 临时运动流，边发送边执行；正常使用由 GUI 生成文件并确认，不是离线文件上传。`sendprog` 不提供仅装载功能，会明确拒绝。 |
| `quit` | 退出 SDK 会话。退出或断线不能当作停机手段。 |

中途停止后，程序可能处于暂停，工具会拒绝从中间重新启动。下一次运行前由现场核对停点和程序，并重新准备到已验收的初始状态。工具不会自动重连、自动重发启动或将普通 STOP 当作急停。断线、反馈不确定或有危险时以现场示教器、柜面和安全回路为准。

## 软件范围

`workstation.cpp` 管理界面和回读联动，`workstation_job.*` 管理原文、路径和源行映射，`workstation_experiment.*` 归档试次和计算路径距离，`workstation_session.*` 管理本地进程和现有 SDK 控制端的会话。`helix_pc.cpp` 是厂家 SDK 控制端源码。`pendant.py` 和 `gcode_import.py` 保留为历史原型。实际 SRC4L6 的 SDK 联机、启停和断网行为仍需现场验证。现场安全联锁由控制系统执行。

### 构建 C++ 工作台

在 MSVC 2022 x64 开发环境使用 CMake 和 Qt 6.8.2 MSVC2022 x64。该版本固定用于 ZIP 读取接口的构建和测试。工作区本机的 Qt 在 `.toolchains/qt`。

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=<Qt根目录>
cmake --build build
```

将 `StepWorkstation.exe` 与 `StepGcodeConverter.exe` 放入 `pc_control/native`，再用 Qt 的 `windeployqt --release --no-compiler-runtime` 收集同目录的运行库，并同步部署配套 `helix_pc.exe`。对其他 Windows 工作站部署时，使用微软官方 MSVC x64 运行时。`--smoke` 验证窗口、转换、工程树和编辑导出，`--source-smoke` 检查厂家虚拟控制器中的 G90/模态运动、SRP 高亮、映射和实验归档，`--home-smoke` 检查设备隔离保存、工程无关的路径预览、低速回程和停止，`--manual-smoke` 检查点动，`--sim-smoke` 运行组合检查。
